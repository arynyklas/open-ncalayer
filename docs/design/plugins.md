# Плагины

Плагин — модуль WebAssembly, который обслуживает запросы сайтов к одному или нескольким `module`-именам протокола NCALayer. Обычно это порт стороннего плагина оригинала: он отвечает тем же JSON, что и оригинал. Плагин работает в песочнице и получает только те возможности ядра, которые заявил в манифесте. Решение и общая модель — в [дорожной карте](roadmap.md): D8 и раздел 3.2.

Формат пакета и манифеста читает и проверяет крейт `oncl-plugin`; он же исполняет плагины (интерпретатор WebAssembly [Wasmi](https://github.com/wasmi-labs/wasmi), без JIT). ABI и гостевой SDK — крейт `oncl-pdk`.

## Пакет

Пакет плагина — zip-архив с расширением `.onclp`. Правила:

- файл пакета — не больше 32 МиБ;
- в корне архива ровно два файла:
  - `plugin.toml` — манифест, не больше 64 КиБ, в UTF-8;
  - `plugin.wasm` — модуль WebAssembly, не больше 16 МиБ; начинается с `\0asm` и версии 1 (байты `00 61 73 6D 01 00 00 00`);
- имена сравниваются побайтно, с учётом регистра;
- пакет отвергается, если в нём есть:
  - каталоги, в том числе пустые;
  - файлы с другими именами, в подкаталогах, с `..`, с абсолютным путём или с `\`;
  - два файла с одним именем;
  - символические ссылки;
  - зашифрованные файлы;
- размеры считаются по байтам, которые фактически получились при распаковке. Размерам из заголовков zip не доверяем: файл, который распаковывается больше заявленного или больше лимита, отвергается;
- sha256 пакета считается от байтов всего файла `.onclp`. Его сверяют с записью в подписанном индексе обновлений ([`update-index.md`](update-index.md)).

Сжатие — `deflate` или без сжатия.

## Манифест

`plugin.toml` — файл TOML. Неизвестные ключи — ошибка: манифест более новой версии формата не читается как более слабый.

```toml
id = "kz.example.echo"
version = "1.0.0"
min_core = "0.2.0"
modules = ["kz.example.Echo"]

[name]
ru = "Эхо"
kk = "Жаңғырық"
en = "Echo"

[description]
ru = "Возвращает запрос обратно"
kk = "Сұрауды кері қайтарады"
en = "Returns the request back"

[replaces]
symname = "kz.example.echo"
version = "1.2.1"

[capabilities]
keys = true
dialogs = true
files = true
http = ["https://tsp.pki.gov.kz/", "https://*.gov.kz/"]
origins = ["https://*.ecc.kz", "http://client2.kazynashylyk.kz"]
http_insecure = ["http://ncalayer.uchet.kz:8080/"]
key_files = true
page_files = true
page_files_ext = ["cms"]
settings = true
shared = true
```

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | Строчные латинские буквы, цифры, `.` и `-`; от 3 до 64 символов; начинается и заканчивается буквой или цифрой; есть хотя бы одна точка (`^[a-z0-9][a-z0-9.-]{1,62}[a-z0-9]$`). Обычно — обратное доменное имя автора |
| `version` | да | Версия плагина, semver |
| `min_core` | да | Минимальная версия ядра, semver |
| `modules` | да | От 1 до 32 `module`-имён, без повторов; каждое — латинские буквы, цифры, `.`, `_`, `-`, от 1 до 128 символов (`^[A-Za-z0-9._-]{1,128}$`) |
| `name` | да | Название в окне «Плагины»: `ru`, `kk` и `en`, каждое непустое и не длиннее 128 символов |
| `description` | нет | Описание: `ru`, `kk` и `en`, каждое не длиннее 2048 символов |
| `replaces` | нет | Бандл оригинала, который заменяет плагин: `symname` (`^[A-Za-z0-9._-]{1,128}$`) и `version` — версия оригинала как строка OSGi, не semver; непустая, не длиннее 64 символов |
| `capabilities` | нет | Возможности плагина. Всё, что не указано, выключено |
| `builtin` | нет | Зарезервировано для модулей ядра (см. [Встроенные модули](#встроенные-модули)). Пакет с `builtin = true` или с `id`, который начинается с `io.github.arynyklas.openncalayer.builtin.`, не устанавливается |

`replaces` нужен для `accessory`: `getBundles` показывает `symname` и `version` установленных и включённых плагинов, `installBundle` по `symname` находит порт.

Возможности (`capabilities`):

| Ключ | По умолчанию | Что разрешает |
|---|---|---|
| `keys` | `false` | Работа с ключами пользователя: открыть хранилище, подписать |
| `dialogs` | `false` | Показ диалогов |
| `files` | `false` | Чтение и запись файлов, которые пользователь выбрал в диалоге |
| `http` | `[]` | HTTPS-запросы по адресам с указанными префиксами, не больше 32 префиксов |
| `origins` | `[]` | `http_request_ex` к origin самой страницы, если он подходит под один из шаблонов (не больше 32); относительные адреса — только от него |
| `http_insecure` | `[]` | `http_request_ex` по HTTP без TLS под точными префиксами, не больше 8 |
| `key_files` | `false` | `keys_open` хранилища по пути, который назвала страница (нужен `keys`); каждый файл — только после согласия пользователя |
| `page_files` | `false` | `page_file_read` и `page_file_write`: файлы и каталоги, которые назвала страница; каждый файл (каталог) — только после согласия пользователя |
| `page_files_ext` | `[]` | Расширения файлов, которые пишет `page_file_write` (нужен `page_files`): до 16, латинские буквы и цифры, сравниваются без учёта регистра |
| `settings` | `false` | `settings_get`, `settings_put`: настройки плагина на диске |
| `shared` | `false` | `shared_get`, `shared_put`: данные, общие для всех экземпляров плагина (а значит, для всех сайтов) в процессе |
| `builtin` | `false` | Зарезервировано для модулей ядра: функции capability `builtin`. Манифест без `builtin = true` с этим ключом — ошибка |

Окно установки показывает каждую возможность отдельной строкой: префиксы `http`, сайты `origins`, префиксы `http_insecure` со словами «незащищённое соединение», `key_files`, `page_files` с расширениями записи, `settings` и `shared` («делить данные между сайтами»). Обновление, которое добавляет возможности (новые флаги, префиксы и шаблоны, не покрытые прежними, новые расширения), снова спрашивает пользователя.

Префикс `http`:

- начинается с `https://` (строчными буквами);
- без имени пользователя и пароля (`@` до пути), без query (`?`) и fragment (`#`);
- без пробелов, управляющих символов и `\`;
- путь обязателен и заканчивается `/`: `https://a.kz/` и `https://a.kz/api/`, но не `https://a.kz` и не `https://a.kz/api`;
- порт можно указать; без порта — 443;
- в пути нет `;`, `%2f` и `%5c` (в любом регистре): с ними префикс не пропустил бы ни одного адреса (см. ниже);
- хост может быть `*.` и доменом не меньше чем из двух меток (`https://*.gov.kz/`): тогда подходит любой хост под этим доменом по границе метки (`a.gov.kz`, `x.y.gov.kz`), но не сам `gov.kz`, не `evilgov.kz` и не `gov.kz.evil`; `https://*.kz/`, `https://*/`, `https://a*.kz/` и `*.` перед IP-адресом запрещены.

Адрес запроса разрешён, если он тоже `https://` без имени пользователя и без `\`, пробелов и управляющих символов, а также:

- хост совпадает с хостом префикса без учёта регистра;
- порт совпадает с портом префикса; явный `:443` равен отсутствию порта;
- путь начинается с пути префикса;
- если путь префикса не `/`, в пути запроса нет `;`, `%2f` и `%5c` (в любом регистре).

Query и fragment запроса не проверяются. Адреса разбираются так же, как в браузерах (стандарт WHATWG URL): сегменты `.` и `..` в пути (в том числе `%2e%2e`) раскрываются до сравнения. Поэтому `https://a.kz/api/../x` не проходит под префикс `https://a.kz/api/`, а `https://a.kz/apix` не проходит, потому что путь префикса заканчивается `/`.

Закодированные `/` и `\` (`%2f`, `%5c`) и параметры пути после `;` разборщик оставляет как есть, а серверы могут раскрыть их иначе: одни декодируют `%2f` до того, как раскрыть `..`, другие отбрасывают `;…`. Тогда `https://a.kz/api/..%2fsecret` или `https://a.kz/api/..;/secret` попали бы за пределы `/api/`. Поэтому под префиксом с путём, отличным от `/`, такие адреса запрещены.

Запрос отправляется по адресу в той форме, в которой его проверили (после разбора и раскрытия сегментов, без fragment), а не по исходной строке. Хост перенаправлениям не следует: ответ 3xx возвращается плагину вместе с `Location`, и следующий запрос плагина по этому адресу снова проходит проверку.

Примеры для префикса `https://tsp.pki.gov.kz/`:

| Адрес | Результат |
|---|---|
| `https://tsp.pki.gov.kz/tsp` | разрешён |
| `https://TSP.pki.gov.kz/x` | разрешён |
| `https://tsp.pki.gov.kz:443/x` | разрешён |
| `https://tsp.pki.gov.kz.evil/` | запрещён: другой хост |
| `https://tsp.pki.gov.kz@evil/` | запрещён: имя пользователя, хост `evil` |
| `https://tsp.pki.gov.kz:8443/` | запрещён: другой порт |
| `http://tsp.pki.gov.kz/` | запрещён: не HTTPS |

Шаблон `origins` — `https://` или `http://`, хост (или `*.` и домен не меньше чем из двух меток, как в префиксе) и необязательный порт, без пути, query и fragment: `https://*.ecc.kz`, `https://a.kz:8443`. Порт без указания — 443 или 80 по схеме.

Префикс `http_insecure` — как префикс `http`, но `http://`, только точный хост (без `*.`), порт без указания — 80: `http://ncalayer.uchet.kz:8080/`.

## ABI

Версия ABI — `1` (`oncl_pdk::abi::ABI_VERSION`). Плагин — модуль WebAssembly для `wasm32`: 32-битная линейная память, без `start`-функции. Модуль экспортирует:

| Экспорт | Тип | Что делает |
|---|---|---|
| `memory` | память | Линейная память плагина |
| `oncl_abi_version` | `() -> i32` | Возвращает версию ABI; другая версия — плагин не загружается |
| `oncl_alloc` | `(len: i32) -> i32` | Выделяет `len` байт и возвращает адрес; `0` — выделить не удалось |
| `oncl_free` | `(ptr: i32, len: i32)` | Освобождает буфер, который вернул `oncl_alloc` |
| `oncl_process` | `(ptr: i32, len: i32) -> i64` | Отвечает на один запрос |

Экспорты проверяются при загрузке вместе с точными типами. Каждый импорт модуля должен быть host-функцией из модуля `oncl` с типом `(ptr: i32, len: i32) -> i64`. Импорт функции, которой нет в ABI, — ошибка загрузки; импорт функции capability, которую манифест не заявил, — тоже. Хост связывает только функции заявленных capabilities.

Все значения передаются в CBOR, в той форме, в какой их пишет serde (крейт `ciborium`); плагину на другом языке нужно знать её точно:

- структура — map с ключами-строками, равными именам полей (`{"request": …, "origin": …, "locale": …}`); поле со значением по умолчанию (в `oncl_pdk::abi` оно помечено `#[serde(default)]`) можно не передавать;
- байтовая строка — байтовая строка CBOR (major type 2), а не массив чисел;
- `()` и `None` — `null`, `Some(v)` — просто `v`;
- перечисление без данных (`ErrorCode`, `Level`, `Action`, `MessageKind`, `Method`) — текстовая строка с именем варианта в `snake_case`: `"denied"`, `"warn"`, `"key_info"`;
- результат host-функции `HostResult<T>` (`Result` в Rust) — map из одной пары с ключом как есть: `{"Ok": значение}` или `{"Err": {"code": "invalid", "message": "…"}}`.

Результат типа `i64` — это `(ptr << 32) | len`: адрес и длина CBOR-байтов в памяти плагина.

Вызов `oncl_process`:

1. Хост кодирует `Input { request, origin, locale }`: текст запроса страницы, `Origin` соединения (если есть) и язык окон OpenNCALayer (`"ru"`, `"kk"` или `"en"`).
2. Хост вызывает `oncl_alloc`, записывает `Input` в полученный буфер и вызывает `oncl_process(ptr, len)`. Буфер теперь принадлежит плагину.
3. Плагин возвращает `Output { response }` — ответ, который уйдёт странице как есть, — в буфере из своего `oncl_alloc`. Хост читает его и вызывает `oncl_free`.

Host-функция получает свой аргумент `(ptr, len)` в памяти плагина (буфер остаётся у плагина), а результат `HostResult<T>` — `Ok(T)` или `Err(HostError { code, message })` — записывает в буфер, который берёт у `oncl_alloc` плагина; этот буфер плагин освобождает сам. Host-функцию можно вызывать только из `oncl_process`. Вызов из `oncl_alloc` или `oncl_free`, пока их вызывает хост (в том числе пока хост выделяет буфер под результат другой host-функции), — trap.

Хост читает и пишет память плагина только с проверкой границ. Буфер за пределами памяти, `0` из `oncl_alloc` и `Output`, который не разбирается, — ошибка плагина. Аргумент host-функции, который не разбирается, — не trap: функция отвечает `{"Err": {"code": "invalid", …}}`.

Базовые host-функции есть у любого плагина:

| Функция | Аргумент | Результат |
|---|---|---|
| `log` | `LogArgs { level, message }`, `level` — `error`, `warn`, `info`, `debug` | `()`; строка уходит в журнал OpenNCALayer с id плагина и номером сессии, длинная — обрезается до 4 КиБ |
| `now` | `()` | `i64` — время в миллисекундах Unix |
| `random` | `RandomArgs { len }` | байты системного генератора, не больше 1024 |
| `cert_info` | `CertArgs { der }` | `CertInfo`: CN, ИИН, БИН, организация, серийный номер, срок действия (мс Unix), расширенные и обычные назначения ключа, OID алгоритмов подписи и ключа и сертификат в PEM |
| `reply_drop` | `()` | `()`; текущий запрос закончится обрывом соединения без ответа (см. [Ошибки](#ошибки)) |
| `hash` | `HashArgs { alg, data }`, `alg` — `sha1`, `sha256`, `sha512`, `gost34311`, `streebog256`, `streebog512` | хеш данных; ГОСТ 34.311-95 — с параметрами Kalkan, как в подписях |
| `cert_details` | `CertArgs { der }` | `CertDetails`: subject и issuer так, как их пишет Kalkan (`CN=…,SURNAME=…,C=KZ`), типы Kalkan (`SIGNATURE`, `AUTHENTICATION`, `SSL`, `OCSP_RESPONSE_SIGNING`, `TSP_SIGNING`), SKI и AKI строчным hex, серийный номер десятичным числом, адреса OCSP, CA Issuers и CRL, алгоритм подписи ключа (`gost2004`, `gost2015_512`, `rsa_sha256`, `rsa_sha1`), CN издателя (`issuer_cn`; ядро старше `0.1.0-alpha.5` его не пишет) |
| `local_time` | `LocalTimeArgs { unix_ms }` | `LocalTime { offset_seconds }` — смещение часового пояса системы от UTC в этот момент |
| `platform` | `()` | `Platform { os, line_separator }`: `windows`, `macos` или `linux` и разделитель строк системы (`\r\n` в Windows, `\n` в остальных) |
| `ca_list` | `()` | сертификаты CA НУЦ, которым доверяет ядро (DER) |
| `ca_issuer` | `CertArgs { der }` | `Option<Bytes>` — CA из `ca_list`, выпустивший сертификат: по имени издателя, сначала тот, чей SKI совпал с AKI |
| `call_locale` | `LocaleArgs { locale }`, `locale` — `ru`, `kk` или `en` (иначе `invalid`) | `()`; окна ядра показываются на этом языке до конца текущего вызова, следующий вызов снова начинается с языка ядра |
| `pkix_path` | `PathArgs { cert, at }`, `at` — `now`, `not_after_if_expired` (у просроченного сертификата — его notAfter, как у `getSigningEntityDefaultChained` оригинала) или `unix_ms(ms)` | `PathOutcome`: `valid`, `issuer_not_found` — у CA ядра нет издателя, `invalid(причина)` — путь через CA ядра не сходится; не сертификат — `invalid`. Без сети |

У каждой host-функции есть версия ядра, в которой она появилась (`Import::since`). Ядро без функции не загрузит плагин, который её импортирует (неизвестный импорт — ошибка загрузки), поэтому `min_core` плагина должен быть не ниже `since` всех его импортов. Новые функции ABI добавляются новыми импортами со своими типами, `ABI_VERSION` остаётся `1`. Аргументы и результаты существующих функций расширяются только так, что прежний плагин их не замечает: новым полем, которое можно опустить (поле, которого нет, — его значение по умолчанию), и новым вариантом, который бывает только в ответ на новое значение аргумента (`tsp_stamp`: `signers = of_cert` — `no_signer`).

| Функции | `since` |
|---|---|
| `log`, `now`, `random`, `cert_info`, `keys_choose`, `keys_sign_cms`, `keys_sign_raw`, `keys_sign_xml`, `keys_release`, `dialog_message`, `dialog_confirm`, `file_open`, `file_save`, `http_request` | `0.1.0-alpha.3` |
| Остальные функции этого раздела: `reply_drop`, `hash`, `cert_details`, `local_time`, `platform`, `ca_list`, `ca_issuer` и новые функции `keys`, `dialogs`, `files`, `http`, `page_files`, `settings`, `shared` | `0.1.0-alpha.4` |
| `call_locale`, `pkix_path`, функции capability `builtin` (`core_*`, `dialog_csr`, `dialog_import`, `keystore_*`, `tokens_id_card`), `keys_flow_open`, `keys_flow_pick`, `keys_describe`, `tokens_scan`, `dialog_reader`, `file_choose_kind` | `0.1.0-alpha.5` |

Версия в `since` — версия ядра, в которой функция впервые вышла в релиз. Уже выпущенная версия ядра в `since` новой функции не ставится: если функция добавлена после выпуска, `since` и версия рабочего пространства поднимаются до следующей предварительной версии.

Функции capabilities — в разделе [Capabilities](#capabilities). Типы аргументов и результатов — модуль `oncl_pdk::abi`.

### Экземпляры

Экземпляр плагина создаётся на сессию — одно WebSocket-соединение или один виртуальный сокет моста — и живёт до её закрытия: состояние плагина (глобальные переменные, выделенная память, ключи) сохраняется между запросами сессии, другие сессии его не видят. Сессия `0` (без сессии) получает экземпляр на один вызов. В процессе живёт не больше 64 экземпляров, и их линейная память вместе (как она измерена при создании экземпляра и после каждого вызова) не больше бюджета памяти: при нехватке закрывается давно не использованный незанятый экземпляр, а если заняты все — запрос, которому нужен новый экземпляр, получает `PLUGIN_ERROR`. Память экземпляра WebAssembly не уменьшается, поэтому экземпляр, чья память после вызова больше порога, закрывается, и следующий запрос сессии получает новый.

## Ошибки

Если плагин не справился с запросом — trap (в том числе паника гостя), кончилось топливо, память выросла бы сверх лимита, буфер вышел за пределы памяти или за лимит, ответ не разбирается как `Output`, — страница получает:

```json
{"success":false,"errorCode":"PLUGIN_ERROR"}
```

Экземпляр после такой ошибки больше не вызывается: следующий запрос сессии получает новый экземпляр. Причина пишется в журнал.

Обрыв без ответа: если плагин во время запроса вызвал `reply_drop`, ответ не отправляется, а соединение закрывается так же, как на запрос, который не является объектом JSON: TCP-соединение — без кадра Close, виртуальный сокет моста — кадром `close`, после которого расширение закрывает сокет страницы с кодом 1006. Так оригинальные модули отвечали на исключение, выброшенное до ответа. Флаг действует только на текущий вызов; `Output` плагин возвращает всё равно (не разбирается — `PLUGIN_ERROR`, обрыва нет). Встроенный модуль при сбое тоже обрывает соединение, см. [Встроенные модули](#встроенные-модули).

Ошибка host-функции — не ошибка плагина: плагин получает `HostError` и решает сам, что ответить странице.

| Код | Когда |
|---|---|
| `denied` | Не разрешено: адрес вне префиксов `http`, адрес TSA, OCSP или CRL вне хостов PKI |
| `invalid` | Неверные аргументы: CBOR не того типа, неизвестное хранилище, handle, за которым нет ключа |
| `limit` | Превышен лимит: размер, число ключей, длина текста |
| `failed` | Операция не удалась: ввод-вывод, сеть, подпись |

Отказ пользователя — не ошибка: выбор ключа и открытие файла возвращают `None`, вопрос — `false`, сохранение — `None`.

`HostError` может нести поле `cause` — стабильную строку `<область>.<вариант>` (константы `oncl_pdk::abi::cause`, весь список — `cause::ALL`), по которой гость отличает сбои ядра друг от друга так, как прежние модули различали варианты ошибок ядра. Поле необязательно: ядро без него его не пишет, гость без него его не читает, ошибка без причины кодируется теми же байтами, что и раньше. Сообщение (`message`) у таких ошибок — текст ошибки ядра.

| Область | Причины | Где |
|---|---|---|
| `cms` | `no_encapsulated_data`, `unknown_algorithm`, `malformed`, `cert_not_found`, `digest_mismatch`, `bad_signature`, `signing_certificate_mismatch`, `constraint` | `keys_sign_cms`, `keys_sign_cms_ex`, `tsp_stamp` (CMS не читается) |
| `xml` | `parse`, `doctype`, `too_large`, `too_deep`, `xpath`, `constraint`, `unsupported_algorithm`, `no_signature`, `bad_digest`, `bad_signature` | `keys_sign_xml`, `keys_sign_xml_ex`, `keys_sign_xades` |
| `key` | `malformed`, `unknown_key_algorithm`, `unsupported`, `mismatch`, `bad_signature`, `not_exportable`, `token` | `keys_sign_raw`; сбой ключа внутри CMS или XML — тоже причина `key.*` |
| `tsp` | `http`, `status`, `content_type`, `rejected`, `nonce_mismatch`, `imprint_mismatch`, `unsupported_imprint_algorithm`, `policy_mismatch`, `no_tsa_certificate`, `clock_skew`, `malformed` | метка времени `keys_sign_cms`; неверный CMS внутри — причина `cms.*` |
| `page_file` | `not_found`, `too_large` | `file_open`, `file_open_ex` |
| `file` | `unknown_kind` | `file_choose_kind` |
| `keystore` | `unknown_algorithm`, `keystore_file_not_found`, `unsuited_storage`, `inappropriate_cert`, `wrong_password`, `wrong_password_pattern`, `change_password_constraint`, `extension_not_found`, `unsupported_storage`, `invalid_request`, `malformed`, `io`, `pkcs12` (`cause::KEYSTORE`) | `dialog_csr`, `keystore_install_cert`, `keystore_change_password` |
| `keystore.folder` | `refused` (папку страница назвать не может), `missing` (не существующая папка; у `keystore_new_key` — ещё и не по абсолютному пути) | `keystore_new_key`, `keystore_install_cert` с `Folder::Page` |
| `keystore.generate`, `csr`, `keystore.write` | вариант `keystore.*` после шага: `keystore.generate.unknown_algorithm`, `csr.invalid_request`, `keystore.write.io` (`cause::NEW_KEY_STEPS`, проверка — `cause::is_known`) | `keystore_new_key`: шаг ключа, запроса или файла |

## Встроенные модули

Модули `kz.gov.pki.knca.basics`, `kz.gov.pki.knca.commonUtils`, `kz.gov.pki.knca.applet.Applet` и `kz.gov.pki.ncalayerservices.accessory` переходят в гостей WebAssembly того же ABI, вшитых в ядро (`oncl_plugin::Builtins`). Встроенный модуль:

- читается из `plugin.toml` с `builtin = true` и `id` под префиксом `io.github.arynyklas.openncalayer.builtin.` — только из бинаря ядра, не из пакета;
- не устанавливается и не удаляется, его нет в окне «Плагины»; плагин не может занять имя его модуля (`ModuleTaken`, владелец `OpenNCALayer`);
- исполняется с доверием ядра (`Trust::Builtin`): окна без строки источника (`source` пуст, `detail` выбора ключа — без имени плагина), `page_file_read` читает файл без окна согласия, метки времени, OCSP и CRL идут через транспорт ядра к любому адресу, как у прежних модулей, а TSA `basics` — та, что задана ядру (`HostServices.tsa`), доступны функции capability `builtin`;
- обновляется только вместе с ядром.

Модули вшиты в бинарь парами `plugin.toml` + `plugin.wasm` (не пакетами `.onclp`): их собирает `build.rs` демона (`oncl-builtins-build`, профиль `builtin-wasm`, цель `wasm32-unknown-unknown`) или берёт готовыми из каталога `ONCL_BUILTINS_DIR` со сверкой его `SHA256SUMS`; `version` и `min_core` манифеста равны версии ядра. Сейчас вшиты `kz.gov.pki.ncalayerservices.accessory` (крейт `oncl-builtin-accessory`) и `kz.gov.pki.knca.basics` (крейт `oncl-builtin-basics`); `commonUtils` и `Applet` пока нативные. Пока у `basics` остаётся и нативный код, тест `oncl-builtin-tests/tests/differential.rs` подаёт одни и те же запросы обеим реализациям и сравнивает ответы и все показанные окна: подписи ключами RSA при фиксированных часах — байт в байт, а то, что случайно по природе (сгенерированные ключи, nonce и подпись метки времени), — по структуре. sha256 каждого модуля пишется в журнал при старте, а `openncalayer builtins` печатает строки `<id> <версия> <sha256>`. Модуль, который не загрузился при старте, — фатальная ошибка: код выхода 1, и новая версия откатывается проверкой здоровья обновления.

Экземпляры встроенного модуля не привязаны к сессии. Вызов берёт любой незанятый экземпляр модуля или создаёт новый; после вызова экземпляр отпускает ключи, пароли, согласия и PIN страниц и возвращается в пул. Незанятых экземпляров на модуль хранится не больше двух; экземпляр, чья память после вызова больше порога, закрывается. Живых экземпляров модуля (занятых и незанятых) не больше лимита; когда заняты все, вызов ждёт, пока один освободится, как нативный модуль ждал очереди окон. Встроенных модулей не больше четырёх, и на 32-битных системах их экземпляры при наибольшей памяти умещаются в 1,5 ГиБ адресного пространства (это проверяется при сборке). Пул отдельный от пула плагинов и не делит с ним лимит в 64 экземпляра. Общее для процесса состояние модуль держит в `shared_*` (на всё время жизни процесса).

Сбой встроенного модуля (trap, топливо, память, неверный `Output`, паника хоста) — не `PLUGIN_ERROR`: соединение обрывается без ответа, как при панике прежнего нативного модуля, причина пишется в журнал на уровне `error`; экземпляр закрывается, следующий вызов получает новый.

| Что | Лимит встроенного модуля |
|---|---|
| Линейная память экземпляра | 2 ГиБ на 64-битных системах, 384 МиБ на 32-битных |
| Память экземпляра, после которой он закрывается по окончании вызова | 64 МиБ на 64-битных системах, 16 МиБ на 32-битных |
| Незанятые экземпляры на модуль | 2 |
| Живые экземпляры на модуль | 32 на 64-битных системах, 1 на 32-битных |
| Топливо на вызов | 200 000 000 000 |
| Буфер между ядром и модулем | 512 МиБ на 64-битных системах (ответ с CMS самого большого сообщения больше сообщения), на 32-битных — как память экземпляра |

`keys_choose` показывает те же окна, что `PKIExtras.sign`: выбор хранилища (PKCS#12 и JKS; по умолчанию оба), пароль, затем выбор ключа. В окнах видны сайт, название плагина и `detail`. `filter` — те же условия, что `signerParams` и `signingParams`: назначения ключа, ИИН, БИН, серийный номер, просроченные, цепочка CA (по умолчанию — CA НУЦ; пустая — без построения пути и OCSP) и проверка OCSP. Имена токенов в `storages` (`AKKaztokenStore`, `AKKZIDCardStore`, …) при включённой поддержке токенов (экспериментальная, по умолчанию выключена) дают в окне хранилища считыватели с носителем и поле PIN-кода; при выключенной эти строки неактивны, как в `PKIExtras.sign`.

`keys_select` добавляет к `filter` условия `more` (недоступный ключ виден в окне с причиной): `any_ext_key_usages` — хотя бы одно из назначений; `exclude_ext_key_usages` — ни одного из них; `knca_types` — хотя бы один тип Kalkan (`SIGNATURE`, `AUTHENTICATION`, …; неизвестное имя — `invalid`); `tin` — БИН сертификата, а если его нет — ИИН; `key_usage` — все биты из `digital_signature`, `non_repudiation`, `key_encipherment`, `key_agreement`; `obsolete_auth` — запрошенный clientAuth принимает и любой сертификат ГОСТ 2015-512, и sha256RSA с keyEncipherment. `initial_path` подставляется в окно хранилища, если страница вправе назвать этот путь (локальный файл или сетевой путь, ранее выбранный пользователем в окне ядра); иначе окно открывается как обычно. `order` — порядок ключей в окне по началу срока действия: `newest_first` (по умолчанию) или `oldest_first`.

`keys_open` открывает хранилище, которое назвал плагин, без окна выбора: `source` — `page_path` (путь от страницы), `bytes` (само хранилище) или `terminal` (считыватель токена); `password` — `text` или `secret` (id пароля из `dialog_password`, который плагин не видел). Путь от страницы:

- разрешён только с `key_files = true` в манифесте, иначе `denied` (проверяется при вызове: функция одна и для байтов);
- читается по правилам путей страницы: устройства (`\\.\…`), каналы и каталоги — `not_found`, сетевой путь — только выбранный ранее в окне ядра, файл больше 64 МиБ — `corrupt`; ничего не читается до согласия;
- пару (сайт, путь к файлу) пользователь разрешает в окне ядра «Сайт … через плагин … просит открыть хранилище ключей: <путь>» — один раз за сессию; отказ или закрытое окно — `declined`.

Байты хранилища открываются без окна: они и пароль уже есть у страницы. Хранилища — PKCS#12 и JKS. Хранилище PKCS#12 читается один раз; если в нём больше 16 ключей или больше 4 зашифрованных частей (safe), оно — `corrupt`, и это выясняется до проверки пароля и вывода ключей из него (ключи в зашифрованной части считаются после её расшифровки, но до расшифровки любого ключа). Если все ключи хранилища не помещаются в свободные handle — `limit`, и не открывается ни один.

Токен (`terminal`) открывается в названном считывателе с PIN-кодом из `password`: все ключи носителя с сертификатом, по handle на каждый. PIN `text` пришёл от страницы (или плагина), и носителю он уходит только с согласия пользователя: окно ядра называет сайт, плагин, носитель, считыватель и, если носитель их сообщает, оставшиеся попытки. Согласие даётся один раз на (сайт, считыватель) в экземпляре; при двух попытках и меньше окно появляется перед каждым PIN; после неверного PIN следующий снова требует согласия. PIN `secret` пользователь сам ввёл в окне ядра и уходит без вопроса, но отвергнутый носителем — только с согласием (повтор того же пароля). Ядро само PIN не повторяет. Отказ или закрытое окно — `declined`, носителю не отправлено ничего ([tokens.md](tokens.md#pin-от-страницы)). Ответы:

- поддержка токенов выключена, службы смарт-карт нет, в считывателе нет носителя этого хранилища или он извлечён, хранилище облачное — `no_device`;
- неверный PIN — `wrong_password { tries_left }`: число попыток сообщают Kaztoken, удостоверение личности и AKey; один вызов тратит не больше одной попытки;
- PIN, который носитель не примет (не ASCII; у удостоверения — не 4 символа), — `wrong_password { tries_left: None }` без единой команды носителю;
- PIN заблокирован — `blocked`; носитель без ключей с сертификатом — `no_keys`; ошибка носителя или службы — `failed`.

Handle ключа токена держит PIN-код в памяти ядра до `keys_release` или конца экземпляра (затем память обнуляется): каждая подпись — отдельное подключение к носителю с проверкой PIN, после которого карта сбрасывается. Если носитель отверг PIN, handle больше его не отправляет. Подпись носителя проверяется открытым ключом сертификата, прежде чем плагин её получит. Писать на токены (создавать ключи, записывать сертификаты) плагины не могут.

`keys_sign_cms_ex` собирает CMS по профилю плагина в одном месте с `keys_sign_cms`: `content` — `data` (подписываются данные) или `digest` (готовый хеш идёт в messageDigest как есть, в CMS не вкладывается); `cosign` — `auto` (подписанный CMS с вложенным контентом подписывается вторым подписантом, как `createCAdES`), `never` или `into` (новый подписант добавляется в данный CMS, подписывается `content`); `econtent_type` — OID типа содержимого (и атрибута contentType); `digest` — только хеш алгоритма подписи сертификата, другой — `invalid` (получатели НУЦ проверяют только эту пару). `attrs`: флаги contentType, messageDigest, signingCertificateV2 (SHA-256 сертификата), `signing_time { at: now | unix_ms, form: auto | utc | generalized }` и `extra` — атрибуты плагина: OID и значения готовым DER (значение, которое не разбирается как DER, и тип, который уже добавил флаг, — `invalid`); атрибуты ложатся в DER SET в порядке сортировки. Без единого атрибута подписываются сами данные. `certificates` — `signer`, `chain` (цепочка `keys_chain`) или `extra` (сертификат подписанта и данные). `timestamp` — метка TSA на новом подписанте (как `tsp_stamp` с `replace`).

Метки времени, OCSP и CRL запрашивает ядро, а не плагин, и только у хостов PKI: `tsp.pki.gov.kz`, `ocsp.pki.gov.kz`, `crl.pki.gov.kz`, `pki.gov.kz`, `test.pki.gov.kz`, `crl.root.gov.kz`, `crl1.root.gov.kz` (на двух последних — CRL удостоверяющих центров НУЦ) и их поддоменов, по `http://` или `https://`. Адрес задаёт `PkiUrl`: `default` (`http://tsp.pki.gov.kz`, `http://ocsp.pki.gov.kz`), `fixed` (адрес) или `from_cert` (адрес из сертификата: OCSP — authorityInfoAccess, TSA — time-stamping в subjectInfoAccess или authorityInfoAccess; сертификат без адреса — `failed` с `other`). Адрес другого хоста, в том числе из сертификата и точки распространения CRL, — `denied`. Таймаут — от 1 мс до 60 с, повторов метки — не больше 10, иначе `invalid`. `PkiMethod`: `get` (base64 запроса после `/` как есть), `get_url_encoded` (base64 в кодировке URL, как NCALayer), `post { content_type }` (без типа — тип протокола), `post_with_path` (POST тела на адрес GET), `get_under(n)` (GET, пока закодированный запрос короче `n`, иначе POST). `Nonce`: `none`, `random(n)` или `value(bytes)`.

Перенаправлениям ядро при этих запросах не следует (3xx — это ответ), так что запрос не уходит с хостов PKI, даже если ответ указывает на другой адрес. Каждый запрос ядра к хостам PKI — в том числе повтор метки, OCSP о каждом подписанте и скачивание каждого CRL — входит в лимит 64 HTTP-запросов за вызов (раздел [Лимиты](#лимиты)); сверх лимита запрос не отправляется, а результат — сетевой сбой с `kind = other`.

`TsaChoice` — `basics` (Стрибог-512, политика 1.2.398.3.3.2.6.4), `kalkan` (SHA-256, политика 1.2.398.3.3.2.6.2), оба — GET с кодировкой URL на `tsp.pki.gov.kz`, или `custom(TsaSpec { url, method, hash, policy, nonce, cert_req, retries, timeout_ms, check_skew_ms, require_tsa_eku })`. Ответ TSA проверяется всегда: HTTP 200 с `application/timestamp-reply`, статус granted, подпись токена, nonce, отпечаток и политика запроса (без политики — любая), с `require_tsa_eku` — назначение timeStamping у подписанта токена, с `check_skew_ms` — genTime не дальше от часов ядра. `tsp_stamp` ставит метку на подписантов `signers` (`last`, `index(i)`, `all_unstamped` или `of_cert(сертификат)` — первого подписанта этого сертификата, как его находит Kalkan), заменяя прежнюю (`replace`) или добавляя ещё одну (`append`); в атрибут идёт токен (`token`) или весь `TimeStampResp` (`whole_response`). CMS, который не читается, — `invalid` с причиной `cms.*` и текстом ошибки ядра.

`ocsp_fetch` спрашивает о сертификате, издатель которого — `host_cas` (CA ядра), `given` или первый из `verifies_cert`, чей ключ проверяет подпись сертификата (не найден — `invalid`); `cert_id_hash` — хеш CertID, `nonce` — расширение nonce запроса. Ответ — каким пришёл, с `BasicOCSPResponse` и статусом сертификата; с `check` ответ проверяется как проверки OCSP ядра (ответчик по цепочке CA ядра с OCSPSigning и nocheck, подпись, актуальность, CertID, эхо nonce), а то, что не так, — `problem` (`responder_unverified`, `ocsp_stale`, `nonce_mismatch`, `malformed`), и тогда статус не сообщается. `crl_fetch` скачивает полный CRL из точек распространения сертификата и, если у сертификата есть FreshestCRL, дельта-CRL (без полного не используется); статус по дельте (запись removeFromCRL — не отозван) решает поверх полного.

Сетевой сбой — не ошибка host-функции, а `NetFailure { stage, kind, address, detail }`: `stage` — `tsp`, `ocsp`, `crl`; `kind` — `unknown_host`, `connect`, `timeout`, `tls`, `http(status)`, `invalid_response`, `rejected(status)`, `clock_skew`, `other`; `address` — хост; `detail` — текст ошибки ядра (у метки времени — как в сообщениях commonUtils).

`cms_verify` проверяет каждого подписанта отдельно и сообщает о каждой проверке `ok`, `skipped` или `fail(problem)`: `signature` — подпись над подписанными атрибутами и messageDigest над контентом (`data` — контент открепленной подписи; без него — `no_content`; `digest_mismatch`, `bad_signature`, `no_signer_cert` — в CMS нет сертификата подписанта, `malformed` — подписант не читается); `ess_cert_id` — signingCertificateV2 против сертификата (`ess_cert_id_mismatch`; без атрибута — `skipped`); `validity` — срок действия сертификата (`expired`, `not_yet_valid`); `path` — путь через CA (`unknown_ca` — издатель не найден, `path_invalid` — путь не сходится); `revocation` — статус (`revoked { at_ms, reason }`, `status_unknown` — ответчик не знает сертификат или ответ о другом, `responder_unverified`, `ocsp_stale`, `crl_invalid`, `malformed`, `net(NetFailure)`); `tsp` — метка времени подписанта, если есть (`tsp_imprint_mismatch` — метка другой подписи, `tsp_invalid` — не проверяется или у сертификата TSA нет пути на её genTime). Время проверки `at`: `now`, `signing_time` (атрибут signingTime) или `tsp_time` (genTime проверенной метки); без атрибута или метки — сейчас. Путь строится на это время, сдвинутое в срок действия сертификата (срок — отдельная проверка). `chain`: не задан — CA ядра, `[]` — путь не строится, список — эти CA (они же — доверенные для ответчиков OCSP). `revocation`: `none`; `embedded_ocsp` — только ответ OCSP из CMS (атрибут id-pkix-ocsp-basic `1.3.6.1.5.5.7.48.1.1` — `OCSPResponse` или `BasicOCSPResponse`, в OCTET STRING или без, подписанный или нет; или id-ri-ocsp-response в `crls`), проверенный на время `at`; `live_ocsp` — ответ из CMS, если есть, иначе ответчик сертификата (GET, CertID SHA-1); `live_ocsp_then_crl` — и CRL, если ответчик не дал проверенного ответа. Отзыв после времени проверки не считается: подпись сделана раньше. Ответчики и точки распространения из сертификатов спрашиваются только на хостах PKI, без перенаправлений; другой хост — `net` с `kind: other`. `require_key_usage` — из сертификатов, названных идентификатором подписанта, берётся первый со всеми указанными битами keyUsage. `first_signer_only` — только первый подписант.

`keys_sign_xml_ex` подписывает XML так, как ждут получатели плагина; незаданные поля дают подпись `keys_sign_xml`. `placement`: `document_element` (последним ребёнком корня), `first_child_of_document` (последним ребёнком первого узла документа; если это комментарий или PI — ошибка, как у оригинала) или `parent` (в элемент XPath `parent`, только с ним). `namespaces` (префикс → URI) и `other_prefix_uri` (URI любого другого префикса) переводят XPath на сравнение по пространствам имён: имя без префикса — без пространства имён, несвязанный префикс — ошибка; без них имена сравниваются как написаны (и `SOAP-ENV:` — пространство SOAP 1.1). `signature_method` — известный URI (RSA-SHA256 `xmldsig-more`, ГОСТ 2004 и 2015-512 Kalkan), подходящий ключу; подписи RSA-SHA1 (`xmldsig`, `xmldsig-more`) не делаются — отказ. `digest_method` — URI дайджеста (по умолчанию — парный методу подписи). `signed_info_c14n` — канонизация SignedInfo; `transforms` — `enveloped` первым, затем не больше одной канонизации; целый документ — только с `enveloped`. `signature_id` — атрибут `Id` подписи; `signing_time_object` — `ds:Object/ds:SignatureProperties/ds:SignatureProperty Id="<property_id>" Target="#<signature_id>"` с неквалифицированным `<timestamp>` и, при `target_ref`, вторая ссылка на него с теми же преобразованиями. `strip_whitespace` — без переводов строк между элементами подписи; `base64_line_breaks: false` — base64 одной строкой. `output`: `as_is` (байты документа с вставленной подписью) или `serialize { declaration, standalone_no, trim }` — как запись JDK `Transformer`: своё объявление XML (`<?xml version="1.0" encoding="UTF-8"?>`, с `standalone="no"`) вместо исходного, без пробелов до первого узла, с `trim` — и по краям; остальное — исходные байты. Ошибка подписи — `failed`.

`xml_verify` проверяет каждую подпись документа сертификатом её `KeyInfo` (как при проверке подписей ядром: более поздние подписи-дети корня не входят в то, что подписали более ранние) и возвращает их в порядке документа; сертификат, который не читается, — пустые байты. Документ не разбирается — `invalid`.

`keys_sign_xades` делает подпись XAdES-BASELINE (XAdES 1.3.2) всего документа: enveloped `ds:Signature` последним ребёнком корня, с `Id` и `ds:Object` с `xades:QualifyingProperties`. `SignedProperties` — `SigningTime` (время ядра, UTC) и `SigningCertificateV2` (SHA-256 сертификата подписанта); их подписывает вторая ссылка с `Type="http://uri.etsi.org/01903#SignedProperties"` и Exclusive XML Canonicalization. Уровень `t` добавляет `SignatureTimeStamp` над элементом `ds:SignatureValue` в Exclusive XML Canonicalization (TSA `tsa`, хеш — её); `lt` — ещё `CertificateValues` (сертификаты `chain`, от издателя подписанта вверх) и `RevocationValues` о подписанте и о каждом сертификате `chain`, кроме самоподписанного корня, издатель — из `chain` (издателя нет в `chain` — `invalid`): ответ OCSP от ответчика из AIA сертификата (`OCSPValues`), а у сертификата без адреса ответчика (как у промежуточных CA НУЦ) — CRL из его точек распространения, полный и, если есть FreshestCRL, дельта (`CRLValues`). Сертификат без ответчика и без точки распространения, недоступный CRL или CRL, который не проверяется, — подписи нет (`failed` со `stage = crl` или `invalid` с `crl_invalid`): пробела в данных об отзыве не бывает; сертификат, отозванный по OCSP или CRL, — `invalid` с `revoked`. Метка времени, OCSP и CRL — только к хостам PKI, как у `tsp_*`, `ocsp_fetch` и `crl_fetch`. URI алгоритмов — по сертификату, как у `keys_sign_xml` (ГОСТ 2015-512, ГОСТ 2004, RSA-SHA256), или из `signature_method`/`digest_method`; подписи RSA-SHA1 не делаются. Подпись проходит `xml_verify`; побайтное совпадение с другими реализациями XAdES не цель.

Закрытый ключ остаётся в ядре: плагин получает только handle — номер ключа в своём экземпляре. Номера идут по возрастанию и не повторяются, поэтому handle после `keys_release` не может указать на другой ключ. Handle действует до `keys_release` или до конца экземпляра; handle другого экземпляра, освобождённый или неизвестный — `invalid`.

#### Потоки выбора ключа

`keys_flow_open` и `keys_flow_pick` — окна выбора ключа ядра по частям, с правилами, которыми различались встроенные модули. Поток живёт до конца вызова `oncl_process`; за вызов открывается не больше 4 потоков, отменённое окно хранилища тоже считается. Индикатор занятости показывается с ответа в окне хранилища до первого окна ключа потока (или до конца вызова). Правила `FlowArgs`:

- `storages` — хранилища окна в этом порядке, повторы остаются; пустой список — окно без хранилищ (в отличие от `keys_choose`, где пустой список — PKCS12 и JKS); неизвестное имя — `invalid`;
- `readers`: `live` — считыватели с носителем, найденные при открытии окна (при включённой поддержке токенов); `fixed([{ storage, reader }])` — эти, первым первый; каждый должен сейчас держать носитель своего хранилища, иначе `invalid`; `none` — строки токенов неактивны. После ошибки токена окно открывается снова с тем же считывателем (у `live` — только для ответа токеном), после ошибки файла — с тем же путём;
- `start`: `recent` — последний открытый файл, `page(путь)` — путь страницы, если страница вправе его назвать (иначе окно открывается пустым, а не с ошибкой), `empty`; `remember` — путь открытого файла становится последним (считыватель не запоминается);
- `detail` — строка обоих окон до 1 КиБ, у плагина с его названием впереди;
- `non_empty_password` — пустой пароль отвергается; `inner_password_policy` — пароль ключей внутренних систем: 8–32 символа, латинские заглавная и строчная, цифра и один из `#$^+=!*()@%&_-`; `same_storage` — ответ не предложенным хранилищем отвергается до чтения;
- `file`: `open` — любой файл, который открывает система; `chosen` — обычный файл на диске до 64 МиБ, в том числе на сетевом диске, но не устройство;
- `knca_types` — в окне только ключи этих типов Kalkan (неизвестный тип — `invalid`); `none` — ошибка окна хранилища, когда ключей не осталось (`no_keys`, `no_signing_keys`, `no_auth_keys`); `empty_is_none` — пустое хранилище тоже получает её;
- `order` — `store`, `newest_first`, `oldest_first` (по notBefore); `checks` — `settled` (любой ключ можно выбрать) или `live { filter, more }` (условия `keys_select` и OCSP, окно ключа следит за проверками, которые начинаются при первом выборе);
- `skip_blocked_reader` — считыватель, носитель которого ответил «PIN заблокирован», в этом потоке больше не пробуется.

### `dialogs`

| Функция | Аргумент | Результат |
|---|---|---|
| `dialog_message` | `MessageArgs { kind, text }`, `kind` — `info`, `warning`, `error` | `()` — когда пользователь закрыл окно |
| `dialog_confirm` | `ConfirmArgs { text }` | `bool`: `true` — «Да»; «Нет» и закрытое окно — `false`. Кнопка по умолчанию — «Нет» |
| `dialog_password` | `PasswordArgs { title, label, ok, cancel, allow_empty }` | `Option<SecretRef { id }>` — пароль остаётся в ядре, плагин получает его номер для `keys_open`; отмена — `None` |
| `dialog_choice` | `ChoiceArgs { kind, title, text, buttons, default, options }` | `Option<u8>`: номер нажатой кнопки; со списком `options` — номер выбранного пункта, если нажата первая кнопка; закрытое окно, другая кнопка или ничего не выбрано — `None` |

Окно пароля показывает сайт, название плагина, заголовок, текст и кнопки плагина; без `allow_empty` «ОК» не принимает пустой пароль. Пароль живёт в экземпляре и годится только для `keys_open` этого экземпляра. Экземпляр держит 8 последних паролей: девятый вытесняет самый старый, и его номер дальше — `invalid`, как и неизвестный номер; номера не повторяются.

Окно выбора показывает сайт, название плагина, заголовок плагина (без него — вид сообщения), текст как обычный текст, от 1 до 3 кнопок слева направо (`default` — кнопка Enter) и список до 32 пунктов. Текст до 16 КиБ, заголовок, кнопки и пункты до 1 КиБ; иначе — `invalid`, окно не показывается.

### `files`

| Функция | Аргумент | Результат |
|---|---|---|
| `file_open` | `()` | `Option<OpenedFile { path, data }>` — файл, который пользователь выбрал в системном окне |
| `file_save` | `SaveArgs { suggested_name, data }` | `Option<String>` — путь, куда пользователь сохранил |
| `file_choose_kind` | `FileKindArgs { kind, directory }`, `kind` — имя `FileChooser.FileType` оригинала (`P12`, `XML`, `ALL`, …) или пустое для папки | `Option<String>` — путь существующего файла или папки, который выбрал пользователь, без чтения; путь, которого нет, и отмена — `None`; неизвестный тип — `invalid` с `cause = file.unknown_kind`. Начальная папка `directory` — только та, что страница вправе назвать |
| `file_choose` | `ChooseFileArgs { mode, title, filters, initial_dir }`, `mode` — `open` или `directory` | `Option<ChosenPath { path, size }>` — путь, который выбрал пользователь, без чтения; `size` — размер файла, у каталога `None` |
| `file_open_ex` | `ChooseFileArgs` с `mode = open` | `Option<OpenedFile>` — как `file_open`, с заголовком, типами файлов и начальным каталогом плагина; `directory` — `invalid` |

Плагин не называет пути сам: файл выбирает пользователь. Читается только обычный файл на диске (не канал и не устройство), не больше 64 МиБ. Сохранение предлагает только имя файла из `suggested_name` (без каталогов) и пишет атомарно: через временный файл рядом и переименование. Типы файлов — до 16, у каждого до 16 расширений из латинских букв и цифр (приводятся к строчным); начальный каталог берётся, только если страница могла бы его назвать (как для `page_files`) и это каталог. Выбранный сетевой путь (`file_choose`, `file_open_ex`) становится путём, который страница может назвать дальше.

### `page_files`

| Функция | Аргумент | Результат |
|---|---|---|
| `page_file_read` | `PagePathArgs { path }` | `PageRead`: `ok(OpenedFile)`, `not_found`, `too_large`, `declined` |
| `page_file_write` | `PageWriteArgs { dir, name, data }` | `PageWrite`: `written(path)`, `invalid`, `declined` |

Путь, который назвала страница, проходит те же правила, что у встроенных модулей: устройства (`\\.\`, `\\?\GLOBALROOT`) — никогда, сетевой путь — только выбранный ранее пользователем в окне ядра; читается только обычный файл не больше 64 МиБ (каталог, канал, устройство — `not_found`, больше — `too_large`), до согласия файл не читается. Ядро спрашивает пользователя окном с сайтом, плагином и полным путём; согласие запоминается в экземпляре (сессии) на пару (сайт, канонический путь), отказ — `declined`.

`page_file_write` пишет в существующий каталог, который назвала страница; `name` — имя без разделителей, `..`, управляющих и зарезервированных символов Windows, не начинается с `.` и не заканчивается `.` или пробелом, с расширением из `page_files_ext`; иначе — `invalid` без вопроса. Окно согласия показывает полный путь файла; согласие действует на каталог до конца сессии. Запись атомарная, существующий файл заменяется.

### `settings`

| Функция | Аргумент | Результат |
|---|---|---|
| `settings_get` | `()` | `BTreeMap<String, String>` — настройки; без файла или с повреждённым файлом — пустые (повреждение пишется в журнал) |
| `settings_put` | `BTreeMap<String, String>` | `()` — настройки заменяются целиком |

Настройки лежат в `<data>/plugins/settings/<id>.json`, пишутся атомарно, не больше 256 ключей и 64 КиБ JSON (иначе `limit`). Обновление плагина их сохраняет, удаление — удаляет.

### `shared`

| Функция | Аргумент | Результат |
|---|---|---|
| `shared_get` | `SharedKey { key }` | `Option<Bytes>` — значение, если оно есть и не истекло |
| `shared_put` | `SharedPut { key, value, ttl_ms }` | `()`; `value = None` удаляет ключ |

Значения живут в памяти процесса, общие для всех экземпляров одного загруженного поколения плагина, то есть для всех сессий и сайтов; перезагрузка и обновление плагина начинают с пустого. Не больше 64 ключей и 64 КиБ ключей и значений вместе (иначе `limit`). Handle ключа через `shared` в другую сессию не переносится: таблица ключей — в экземпляре.

### `http`

| Функция | Аргумент | Результат |
|---|---|---|
| `http_request` | `HttpArgs { method, url, content_type, body }`, `method` — `get` или `post` | `HttpResponse { status, content_type, location, body }` |
| `http_request_ex` | `HttpExArgs { method, url, relative_to_origin, headers, content_type, body, timeout_ms }` | `HttpResponse` |

Адрес проверяется по префиксам манифеста (см. выше) и отправляется в проверенной форме; вне префиксов — `denied`, ничего не отправляется. Запрос идёт через прокси из настроек OpenNCALayer, только по HTTPS, с лимитами 32 МиБ и 60 с и без следования перенаправлениям: 3xx возвращается плагину с `location`. У GET нет тела. За один вызов `oncl_process` уходит не больше 64 запросов вместе с запросами ядра к хостам PKI; следующий получает `limit` и не отправляется.

`http_request_ex` отправляет запрос, если выполнено одно из условий:

- адрес под префиксом `http` (HTTPS, хост `*.` — по границе метки);
- `relative_to_origin` (адрес разрешается от origin текущего вызова) или абсолютный адрес с тем же origin (схема, хост, порт), и этот origin подходит под шаблон `origins`; HTTP — только если сам origin HTTP. Без origin или с origin, который не является адресом (`null`), — `denied`;
- адрес под префиксом `http_insecure` (HTTP, точный хост и порт).

Остальное, в том числе `file:`, `data:` и другие схемы, — `denied`. Заголовки — только `Cookie`, `User-Agent`, `Accept`, `Accept-Language`, `X-Requested-With` (без учёта регистра; другие — `denied`), не больше 16 и 8 КиБ вместе (иначе `limit`); CR, LF или NUL в заголовке или `content_type` — `invalid`. POST без `content_type` уходит без `Content-Type`. `timeout_ms` — от 1 до 60000. Перенаправлениям хост не следует, как у `http_request`.

## SDK

Плагин на Rust пишется с крейтом `oncl-pdk`. Под `wasm32` он даёт:

- макрос `oncl_pdk::plugin!(handler)`: `handler: fn(&Request) -> String` получает запрос (`text`, `origin`, `locale`) и возвращает ответ странице; макрос экспортирует `oncl_abi_version`, `oncl_alloc`, `oncl_free`, `oncl_process`, а паника плагина перед trap пишется в журнал через `log`;
- обёртки host-функций, которые возвращают `HostResult`: `host::{log, now, random, cert_info, reply_drop}`, `keys::{choose, flow_open, Flow, Key}` (`Flow::{keys, pick}`; `Key::{sign_cms, sign_raw, sign_xml, sign_xml_ex, sign_xades, describe, alias, certificate, handle}`; при удалении `Key` вызывается `keys_release`), `tokens::scan`, `dialogs::{message, confirm, password, choice, reader}`, `files::{open, save, choose, choose_kind, open_ex, page_read, page_write}`, `pki::path`, `http::{get, post, request_ex}`, `settings::{get, put}`, `shared::{get, put}`, для встроенных модулей — `core::{modules, bundles, install_bundle, open_window}` и `builtin::{dialog_csr, dialog_import, new_key, install_cert, change_password, id_card}`, а также `call_host` — вызов любой host-функции с типами ABI;
- `Request::add_info()` и реэкспорт `oncl_protocol::{invoker, orgjson}` и `serde_json`: плагин, который отвечает в диалекте CommonInvoker (как `kz.gov.pki.knca.basics`), вызывает тот же `invoker::invoke`, что и встроенные модули;
- Java-диалекты оригинала для плагинов, которые должны отвечать как оригинал байт в байт (реэкспорт из `oncl-protocol`): `orgjson::{parse, reserialize}` — разбор org.json 20211205 с его текстами ошибок и позицией (`Duplicate key "a" at 11 [character 12 line 1]`), `orgjson::{JObject, JValue, quote}` — запись, как пишет `JSONObject.toString()`: порядок ключей `HashMap` (`JObject::hash_map()` для `new JSONObject()` и бинов, `JObject::from_map(n)` для `new JSONObject(map)`, `JObject::stringer()` для `JSONStringer`), числа без хвостовых нулей, `<\/`, `\u2028`; читатели `orgjson::{opt_boolean, get_boolean, opt_int, get_int, get_object, get_array, array_get_string, …}` с текстами `JSONException`; `javamap` — порядок `HashMap` для любого набора ключей; `javab64::{decode_java, decode_kalkan, encode_mime}`; `javaexc::Throwable` — тексты исключений Java; `legacy::dispatch` — рефлексивный диспетчер `commonUtils` и его клонов (поиск метода по имени и числу аргументов, преобразование массивов, тексты `NoSuchMethodException`/`IllegalAccessException`/`argument type mismatch`, `uuid` через org.json, `null` без `uuid` — обрыв соединения); `invoker::java::invoke_with` — `CommonInvoker` оригинала: `details` с классом исключения (`java.lang.IllegalArgumentException: Supported apiVersion is 2`), порядок `{"body":…,"status":true}` и `{"code":…,"details":…,"message":…,"status":false}`, таблица методов с аннотациями и числом параметров, а для запроса, который не дошёл до `try` оригинала, — выбор `BadRequest::{Reply, Drop, CatchAll}`. Встроенные модули пока отвечают по-прежнему (`invoker::invoke`, свой диспетчер `commonUtils`).

Импортируются только те host-функции, которые плагин вызывает, поэтому плагину без `keys` не нужно заявлять `keys`. `call_host` ссылается на все функции, и плагину с ним нужны все capabilities.

Пример — `crates/oncl-pdk/example`: модуль `io.github.arynyklas.openncalayer.Example`, класс `Example` с методом на каждую возможность (`echo`, `count`, `origin`, `confirm`, `message`, `sign`, `signRaw`, `signXml`, `hold`, `release`, `rawSign`, `open`, `save`, `fetch`) и методами, которые нарочно ведут себя плохо (`spin`, `grow`, `panic`). Сборка:

```sh
cargo build --release --target wasm32-unknown-unknown --manifest-path crates/oncl-pdk/example/Cargo.toml
```

Модуль — `crates/oncl-pdk/example/target/wasm32-unknown-unknown/release/oncl_plugin_example.wasm`; вместе с `plugin.toml` примера он упаковывается в `.onclp`. Пример — отдельный workspace со своим `Cargo.lock`, в релизы он не входит. Тесты `oncl-plugin` собирают его сами в `target/plugin-example`.

## Жизненный цикл

Установленные плагины лежат в `<data>/plugins/`: `state.json` (установленные плагины — версия, sha256 пакета, источник, включён ли, отозван ли; версии, которые здесь не загрузились; случайный `install_id` для раскатки; последний принятый `seq` каталога каждого канала), `packages/<id>-<version>.onclp` и `catalog/<канал>.json` с подписью `.json.minisig`. Каждый файл заменяется атомарно, состояние меняется под одной блокировкой и сохраняется до того, как изменение видно. Повреждённый `state.json` заменяется свежим (в журнал); другая ошибка чтения выключает плагины — окно «Плагины» показывает её.

**Каталог** — записи `plugins` подписанного индекса обновлений канала из настроек (`updates.channel`, по умолчанию — канал версии OpenNCALayer), см. `docs/design/update-index.md`. Он скачивается через 10–60 с после старта, если действующего каталога нет, иначе через 2–10 минут; дальше раз в 6–24 часа, после сбоя загрузки — через 30 минут – 2 часа. Принятый каталог (подпись, `seq` и срок проверены при загрузке) сохраняется; сохранённый каталог при чтении с диска проверяется заново целиком, а уже загруженный в память — только по сроку. Каталог, скачанный по запросу при включённых обновлениях, сразу применяется в фоне. С выключенными обновлениями (`updates.enabled = false`) плановых загрузок и автообновлений плагинов нет; каталог скачивается только по запросу: окно «Плагины», `installBundle`, «Проверить сейчас» в настройках и «Проверить обновления» в меню значка (проверка плагинов идёт в фоне по сохранённым настройкам). Сборка без зашитых ключей каталога не имеет: окно пишет «Каталог плагинов недоступен в этой сборке», плагины ставятся только из файла.

**Старт.** Включённые и не отозванные плагины загружаются из своих пакетов; sha256 файла сверяется с записанным при установке. Плагин, который не загрузился (пакет изменён, нужен более новый OpenNCALayer, модуль занят), остаётся установленным в состоянии «ошибка» и не мешает остальным.

**Установка из каталога** (кнопка «Установить…» или `installBundle`): пакет скачивается только по HTTPS, его размер и sha256 сверяются с индексом, затем `Package::read`, совпадение `id`, `version`, `modules` и `replaces` манифеста с записью индекса, `min_core` и пробная компиляция с проверкой имён модулей (встроенный модуль или модуль другого плагина не занимается). Пакет, не прошедший проверку, помечает версию плохой; сбой сети версию плохой не делает (установку можно повторить, а обновление повторится при следующей проверке каталога). Не делает её плохой и модуль, который уже обслуживает другой установленный плагин: это зависит от установки, а не от пакета; обновление на такую версию не повторяется, пока плагины не изменятся (удаление, выключение, установка или обновление плагина), а установку можно повторить сразу. Ничего не ставится, значок сообщает об ошибке; установку, начатую из окна «Плагины», окно ещё и объясняет на языке интерфейса. Затем окно «Установка плагина» показывает, кто просит (`origin` без управляющих символов, разделителей строк и символов направления текста, не длиннее 128 символов), имя, версию, что плагин заменяет и его capabilities; кнопка «Установить» становится доступной через 1,5 с после появления окна, чтобы клик или Enter, предназначенные другому окну, не установили плагин; «Установить» загружает плагин, записывает пакет и состояние и сообщает «Плагин установлен», «Отмена» или закрытие окна ничего не меняет.

**Установка из файла** («Установить из файла…», фильтр `*.onclp`): те же проверки пакета, `min_core` и модулей, окно с предупреждением: «Этого плагина нет в каталоге OpenNCALayer, его не проверял мейнтейнер…». Если плагин с тем же `id` уже установлен, окно называет его версию и откуда он — из каталога или локальный. Такой плагин помечается «локальный»: каталог его не обновляет и не отзывает.

**Обновление и отзыв.** После каждого принятого каталога (плановой загрузки или «Проверить сейчас» при включённых обновлениях) для каждого плагина из каталога выбирается версия (`choose_plugin`): обновление — с раскаткой, только вверх; с отозванной версии — на лучшую неотозванную, в том числе вниз и без раскатки. Новая версия скачивается и проверяется как при установке, загружается новой «генерацией» и только потом записывается; если что-то не прошло, версия попадает в плохие, а старая продолжает работать. Обновление, которое может не больше установленной версии, не спрашивает пользователя, значок сообщает «Плагин обновлён». Если новая версия может больше — новый флаг `keys`, `dialogs` или `files` или адрес `http`, не покрытый префиксами установленной версии, — она скачивается и проверяется, но не ставится: установленная версия продолжает работать, окно «Плагины» показывает у плагина, что новая версия сможет сверх установленной, с кнопкой «Разрешить обновление», а значок один раз сообщает «Обновление плагина ждёт разрешения». Обновление ставится, когда пользователь его разрешит; если каталог за это время перестал его предлагать, ждать нечего. Отозванная версия без замены выгружается и помечается отозванной (уведомление один раз); она не загружается, пока каталог её не вернёт.

**Во время работы.** Вызов, который идёт, доигрывает на своём экземпляре; следующий вызов той же сессии получает экземпляр новой генерации или `MODULE_NOT_FOUND`, если плагин выгружен. Сбой вызова выбрасывает только его экземпляр.

**Выключение и удаление.** «Выключить» выгружает плагин, «Включить» загружает снова (кроме отозванного). «Удалить» (после вопроса) выгружает плагин и удаляет его пакет и запись.

**Нужный модуль.** Запрос к модулю, которого никто не обслуживает, отвечает `MODULE_NOT_FOUND`, как раньше. Если действующий каталог (без скачивания) предлагает плагин с таким модулем, а он не установлен, значок сообщает «Сайту X нужен плагин «Y»» с кнопкой «Установить…», которая открывает окно «Плагины» (не чаще раза в 10 минут), а окно отмечает плагин «Нужен сайту X». Сообщение (и новое чтение открытого окна) бывает, только когда эта отметка меняется: плагин стал нужен или нужен другому сайту.

## installBundle

`kz.gov.pki.ncalayerservices.accessory` `installBundle` повторяет порядок проверок оригинала: пустой `symname` — `SYMNAME_PARAMETER_IS_EMPTY`; без заголовка `Origin` — `org.json.JSONException: JSONObject["origin"] is not a string.`; затем демон ищет в каталоге неустановленный плагин, у которого `replaces.symname` равен `symname`. Если действующего каталога нет, демон его скачивает; если скачивание уже идёт, дожидается его; всё это — не дольше 10 с, после чего ответ без каталога. Если скачать каталог не удалось (сеть, индекс не опубликован или отвергнут), запросы страниц ещё 5 минут обходятся без каталога и не скачивают его снова; «Обновить каталог», «Установить…» в окне «Плагины» и «Проверить сейчас» скачивают его сразу.

- найден — ответ сразу `{"errorCode":"NONE"}`, а установка (скачивание, проверки, окно подтверждения) идёт в фоне: как и оригинал, ответ не ждёт пользователя. Пока она идёт (в том числе ждёт ответа пользователя), повторный запрос отвечает так же и новую не начинает; о сбое установки, начатой страницей, значок сообщает не чаще раза в 10 минут для каждого плагина;
- не найден, уже установлен (в том числе выключен или отозван) или каталога нет (сборка без ключей, офлайн, индекс истёк, не успел за 10 с) — `BUNDLE_NOT_FOUND_OR_ALREADY_INSTALLED`, а значок сообщает «Сайт {origin} запросил модуль {symname}. Каталог OpenNCALayer не предлагает его установить: его там нет или он уже установлен» с кнопкой «Реестр плагинов» (не чаще раза в 10 минут). `origin` и `symname` показываются без управляющих символов, разделителей строк и символов направления письма, не длиннее 128 символов.

`uuid` запроса возвращается, как раньше. `getBundles` добавляет к бандлам оригинала `replaces.symname → replaces.version` включённых загруженных плагинов, `getServices` — модули плагинов: оба списка живые и видят плагин сразу после установки. `showBundleManager` открывает окно «Плагины».

## Порты

Порты сторонних плагинов оригинала лежат в `plugins/`: 34 каталога `plugins/<short>`, по одному на плагин оригинала, и общие библиотеки в `plugins/common/`. Это отдельный workspace для `wasm32-unknown-unknown`: в workspace ядра и в его релизы он не входит. Один порт собирается в пакет командой `cargo xtask plugin pack plugins/<short>`; job `conformance` в `release.yml` собирает пакеты всех портов, но не публикует их (`docs/dev/release.md`).

В каталоге порта:
- `plugin.toml` — манифест (раздел [«Манифест»](#манифест)): `id` вида `io.github.arynyklas.openncalayer.port.<short>`, имена `module`, которые порт обслуживает, `replaces` — `symname` и версия бандла оригинала, и только нужные порту capabilities;
- `registry.toml` — данные реестра: бандл оригинала (`symname`, версия, поставщик), состояние порта (`full` — всё, что делает оригинал; `partial` — с оговорками; `needs-tokens` — всё, но часть проверяется только на токенах), способ сверки с оригиналом и отличия от оригинала (`[[differences]]`), которые реестр показывает пользователю;
- исходники крейта `oncl-port-<short>`.

Порты по группам D9:

| D9 | Семейство | Порты |
|---|---|---|
| 2 | ecc.kz | market, efactoring, nursign, k2sign |
| 3 | клоны commonUtils | rating1c, xdox, eot, ezsigner, uchet, arta, metadoc |
| 4 | CommonInvoker | idocs, fhs, doodocs, devart, thundercrypt |
| 5 | прочие средние | taxtech, energy, eproc, esf-osdkz, uchet-esf, qiwi, bas, eup, dogovor24, workspace, simourg, motiw |
| 6 | тяжёлые | buhta, acbank, knp, documentolog, qoltanba, skf |

Состояние `full` — у buhta, acbank и doodocs, у остальных `partial`.

Общие библиотеки:
- `oncl-port-kit` (`common/kit`) — то, что плагины оригинала собирали средствами Java: тела `multipart/form-data` байт в байт, `new URL(context, spec)` и origin, zip-архивы, `Properties.storeToXML`, шаблоны `SimpleDateFormat`, ответы семейства ecc.kz;
- `oncl-port-legacy` (`common/legacy`) — общее у клонов commonUtils (рефлексивный диспетчер `oncl_pdk::legacy`): бин `ResponseMessage`, проверки `StorageInfo`, типы ключей и выбор ключа, `KeyInfo`, Base64 Java, тексты сетевых исключений Java;
- `oncl-port-pki` (`common/pki`) — DER в госте (RustCrypto `der`, `x509-cert`, `cms`; без ключей и случайности — подписывает хост): подписанные атрибуты и имена из строк DN, чтение CMS, атрибуты и запрос OCSP ЕСЭДО, доверенные сертификаты Java KeyStore, тексты сертификатов Java и Kalkan.

Диалекты JSON (org.json, порядок `HashMap` Java, диспетчеры) — в `oncl-pdk`. Тесты портов — крейт `oncl-port-tests` (`crates/oncl-port-tests`): он грузит собранный `.wasm` в настоящий хост плагинов с тестовым PKI и, где нужно, эмулятором токенов.

Правила порта:
- **Сохраняется** то, что видит страница: форма ответов, коды и тексты ошибок, порядок проверок, порядок полей (в том числе порядок `HashMap` Java), байты подписей и запросов к серверам.
- **Исправляется** то, что небезопасно или опирается на состояние вне песочницы: подписи на SHA-1 (sha1RSA) не создаются; HTTPS — только с проверкой сертификата и по адресам из манифеста; ключи и пароли не запоминаются между соединениями и не пишутся на диск (то, что порт сохраняет, например путь к хранилищу, идёт через capability `settings`); файлы настроек и кэши оригинала не читаются; пути к файлам от страницы заменяются окнами хоста. Каждое такое отличие записывается в `registry.toml`.
- Токены — только через экспериментальную поддержку ядра ([`tokens.md`](tokens.md)); пока она выключена, хранилища токенов пусты.

Ожидаемые ответы в тестах выведены из поведения оригинала, но байт в байт с оригиналом порты ещё не сверялись: это P10.

Схема `registry.toml` (её единственный читатель — `xtask::registry::ports`; `cargo xtask registry build` отказывается собирать сайт, если хоть один порт её нарушает, и называет все такие порты вместе):

| Поле | Правило |
|---|---|
| `id` | равен `id` из `plugin.toml`, а тот — `io.github.arynyklas.openncalayer.port.<short>`; `<short>` — `^[a-z0-9][a-z0-9-]{0,62}$` |
| `modules` | те же, что в `plugin.toml` |
| `[original]` `symname`, `version` | те же, что `[replaces]` в `plugin.toml`; `symname` — `^[A-Za-z0-9._-]{1,128}$` и не повторяется у двух портов |
| `[original]` `vendor` | 1–256 символов без управляющих |
| `[port]` `status` | `full`, `partial` или `needs-tokens` (всё, но часть проверяется только на токенах) |
| `[port]` `conformance` | `computed` (по коду оригинала) или `confirmed` (на работающем оригинале, P10) |
| `[[differences]]` `ru` | до 64 отличий, каждое — 1–2048 символов без управляющих, кроме перевода строки; показываются как текст, на казахской и английской страницах — с пометкой «на русском» |

Лишние ключи — ошибка. Каждый порт получает на сайте проекта страницу `/plugins/<short>/` (и `/kk/…`, `/en/…`) и строку каталога `/plugins/#<symname>`; новый порт с `registry.toml` попадает на сайт при следующей сборке.

Новый порт: каталог `plugins/<short>` (имя не начинается с `c` — так workspace отделяет порты от `common/`), `plugin.toml` и `registry.toml`, тесты в `oncl-port-tests`; при новых зависимостях — `cargo xtask licenses --plugins`.
