# Аппаратные токены и удостоверение личности

Статус: **экспериментально, по умолчанию выключено.** OpenNCALayer читает ключи и подписывает на PC/SC-носителях шести семейств, которые знает Kalkan. Ни один драйвер ещё не проверялся на настоящем носителе: каждый проверен только на программном эмуляторе своего семейства (крейт `oncl-token`, фича `emulator`). Байты команд повторяют документированные форматы семейств; там, где формат ответа выведен, а не наблюдён, в коде стоит пометка `// Unverified on hardware: …`, а у каждого драйвера — `HARDWARE_VERIFIED = false`.

Включается флажком «Токены и удостоверение личности (экспериментально)» в окне «Настройки…» (ключ `settings.json` `"tokens": {"enabled": true}`). Флажок действует сразу, без перезапуска: для модулей `basics`, `commonUtils`, `Applet` и для плагинов.

## Семейства

| Хранилище | Носитель | Алгоритмы | ATR | Счётчик попыток PIN | Эмулятор | Железо |
|---|---|---|---|---|---|---|
| `AKKaztokenStore` | Kaztoken | ГОСТ 34.310-2004, ГОСТ 34.10-2015 512, RSA | 3 | да | да | нет |
| `AKKZIDCardStore` | удостоверение личности РК | ГОСТ 34.10-2015 512, RSA | 7 | да | да | нет |
| `AKEToken72KStore` | eToken PRO 72K | ГОСТ 34.310-2004, RSA | 1 | нет | да | нет |
| `AKEToken5110Store` | eToken 5110 | ГОСТ 34.310-2004, ГОСТ 34.10-2015 512, RSA | 2 | нет | да | нет |
| `AKJaCartaStore` | JaCarta | ГОСТ 34.310-2004, ГОСТ 34.10-2015 512, RSA (под T=0 — без RSA) | 1 | нет | да | нет |
| `AKAKEYStore` | AKey | ГОСТ 34.310-2004, ГОСТ 34.10-2015 512, RSA | 4 | да | да | нет |

Семейство носителя определяется по ATR (точное совпадение). У удостоверения PIN — ровно 4 ASCII-символа; любой PIN не из ASCII отклоняется до первой команды носителю. Облачное хранилище `ABCloudServiceStore` не поддерживается.

## Что поддерживается

- Список подключённых носителей: `getActiveTokens` (commonUtils), `loadSlotList` (Applet), выбор считывателя в `browseKeyStore`, `keys_terminals` плагинов.
- Окно хранилища (`basics` `sign`, ключи плагинов `keys_choose`/`keys_select`, commonUtils, Applet `signXml`): строки токенов, выпадающий список считывателей с кнопкой «Обновить», поле PIN-кода. Неверный PIN — «Неверный PIN-код. Осталось попыток: N» (если носитель сообщает число), заблокированный PIN — отдельное сообщение.
- Данные удостоверения без PIN: `getPublicPartInfo` (Applet) — `IIN<ИИН> <ФИО>`.
- Подпись: CMS и CAdES, XMLDSig, «сырая» подпись плагинов — те же форматы, что у ключей из файлов (ГОСТ — `r‖s` в порядке Kalkan, RSA — PKCS#1 v1.5). Подпись носителя проверяется открытым ключом сертификата, прежде чем уйти странице: неверная подпись становится ошибкой, а не битой подписью на сайте.
- `keys_open` плагинов с `terminal`: токен в названном считывателе с PIN-кодом от плагина, без окна.

## Что не поддерживается

Запись на носитель: генерация ключей (`genKeyPairAndGetPKCS10`, `generateCsr`), запись сертификата (`setX509CertToKeyStore…`, `importCertificate`), удаление ключа (`deleteEntry`), форматирование (`resetStorage`), смена PIN (`changePassword`). Ошибка в такой записи на непроверенном железе необратима: перезаписанный каталог ключей Kaztoken, занятый запасной ключ удостоверения, отформатированный eToken. Поэтому при подключённом носителе этого семейства такие вызовы отвечают общим кодом ошибки оригинала (`GENKEY_COMMON`, `SETCERT_COMMON`, `COMMON`, `CHANGEPASS_COMMON`), не отправив носителю ни одной команды; без носителя — прежними кодами.

## PC/SC по ОС

| ОС | Служба | Как подключается |
|---|---|---|
| Windows | «Смарт-карта» (SCardSvr) | `winscard.dll`: `SCardEstablishContext`, `SCardReleaseContext`, `SCardListReadersW`, `SCardGetStatusChangeW`, `SCardConnectW`, `SCardBeginTransaction`, `SCardEndTransaction`, `SCardTransmit`, `SCardDisconnect` — все есть в Windows 7 |
| macOS | системная | `PCSC.framework` |
| Linux | `pcscd` (пакеты `pcsc-lite` и `ccid` для USB-считывателей) | `libpcsclite.so.1` открывается во время работы (dlopen); бинарник от неё не зависит и запускается без неё |

Без службы (Linux без `libpcsclite.so.1` или без `pcscd`, остановленная служба Windows) демон работает как обычно: `getActiveTokens` — `[]`, `loadSlotList` — `EMPTY_SLOT`, окно хранилища пишет «Служба смарт-карт недоступна» с подсказкой для своей ОС. Считыватели опрашиваются только по запросу — при открытии окна, кнопкой «Обновить» и при каждом вызове API; фонового опроса нет.

## PIN

- PIN живёт только в памяти демона (`Zeroizing`: память обнуляется при освобождении) и никогда не пишется в журнал.
- Каждая операция — отдельная транзакция: подключение, выбор апплета и сверка серийного номера носителя (на месте другая карта — ошибка), проверка PIN, команды, выход, отключение со сбросом карты. Сброс снимает проверку PIN и для других программ.
- Ключ, открытый в окне или через `keys_open`, держит PIN до конца операции (у плагинов — до `keys_release` или конца экземпляра). Если носитель отверг PIN, ключ больше его не отправляет, чтобы повторные подписи не тратили попытки. Один вызов тратит не больше одной попытки.

## Что видят сайты без запроса

Как и оригинальный NCALayer, демон отвечает без окна на `getActiveTokens`, `loadSlotList` и `getPublicPartInfo`. Пока поддержка включена, любой сайт, открытый в браузере, может узнать, какие носители подключены, и прочитать **ИИН и ФИО** владельца вставленного удостоверения личности. Это одна из причин, почему поддержка выключена по умолчанию. Подписать сайт по-прежнему может только с PIN-кодом: встроенные модули спрашивают его в окне хранилища, а плагин с возможностью `keys` получает его от страницы (`keys_open`), как порты оригинала.

## Эмулятор

Фича `emulator` крейта `oncl-token` (в демоне — фича `token-emulator`) добавляет программные носители всех шести семейств: синтетические ключи из `fixtures/synthetic`, ответы ровно на те команды, что шлют драйверы, счётчики попыток, извлечение карты посреди операции, режим «перепутанные половины подписи». Фичи не входят ни в одну релизную сборку.

Демон, собранный с `--features e2e-prompter,token-emulator`, при `ONCL_TOKEN_EMULATOR=<config.toml>` берёт носители из файла вместо службы смарт-карт и включает поддержку токенов. Формат файла (пути ключей — относительно каталога файла):

```toml
[[reader]]
name = "OpenNCALayer Emulated Kaztoken 0"
kind = "AKKaztokenStore"        # имя хранилища; без kind — пустой считыватель
pin = "123456"
tries = 10                      # необязательно
protocol = "T1"                 # необязательно: "T0" или "T1"
keys = [{ p12 = "fixtures/synthetic/user-gost2015-sign.p12", password = "Qwerty12" }]
# только для AKKZIDCardStore:
id_card = { iin = "123456789012", last_name = "ТЕСТОВ", first_name = "ТЕСТ", middle_name = "ТЕСТОВИЧ" }
```

Необязательны также `serial` (16 шестнадцатеричных цифр), `atr_index` и `fixed_k` (nonce ГОСТ в hex — для подписей, равных программным). Пример — `crates/openncalayer/tests/data/tokens.toml`.

Настоящий PC/SC-бэкенд Linux проверяется в CI (job `tokens-vpcd`): `cargo xtask token-emu --config <toml> [--vpcd host:port]` отдаёт эмулированную карту виртуальному считывателю `vpcd` из vsmartcard (инструмент CI, не линкуется и не поставляется), а `pcscd` видит её как настоящую.

## Трассировка для сообщений о проблемах

`ONCL_TOKEN_TRACE=1` в окружении демона пишет в журнал каждую команду носителю: заголовок, длину и данные команды, слово состояния и длину ответа. Данные команд проверки PIN и входа заменяются на `<redacted N bytes>`, данные ответов не пишутся. В журнал при этом попадают пути к файлам носителя и его серийный номер (в командах выбора и сверки), поэтому журнал с трассировкой стоит просмотреть, прежде чем прикладывать к сообщению.
