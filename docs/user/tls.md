# Сертификат OpenNCALayer (TLS)

## Зачем нужен сертификат

Сайты подключаются к NCALayer по адресу `wss://127.0.0.1:13579`. Это защищённое соединение, поэтому браузер проверяет сертификат сервера так же, как у любого сайта. Если браузер не доверяет сертификату, соединение молча не устанавливается, и сайт пишет, что NCALayer не запущен.

Оригинальный NCALayer приносит свой сертификат с собой. OpenNCALayer выпускает сертификат на вашем компьютере:
- `openncalayer tls init` создаёт **локальный центр сертификации** (CA) и сертификат сервера для `127.0.0.1`;
- в CA зашито ограничение (name constraints): он может подтверждать только `127.0.0.1`, `::1` и `localhost`. Для других сайтов его подпись недействительна, даже если CA установлен в доверенные;
- закрытый ключ CA существует только в памяти во время `tls init` и сразу уничтожается. Новый сертификат этим CA выпустить уже нельзя: перевыпуск — это новый CA (см. «Перевыпуск»).

OpenNCALayer **сам ничего не устанавливает** в хранилища сертификатов Windows, macOS или браузеров. Он печатает инструкцию, а установку выполняете вы.

## Где лежат файлы

Каталог данных:
- Windows: `%APPDATA%\OpenNCALayer`;
- macOS: `~/Library/Application Support/OpenNCALayer`;
- Linux: `${XDG_DATA_HOME:-~/.local/share}/openncalayer`.

Переменная окружения `ONCL_DATA_DIR` заменяет этот каталог (так делают при разработке и тестах).

В подкаталоге `tls/`:

| Файл | Что это |
|---|---|
| `OpenNCALayer-CA.cer` | сертификат локального CA в DER — для Windows |
| `OpenNCALayer-CA.crt` | он же в PEM — для macOS, Linux и Firefox |
| `server.crt` | сертификат сервера (и цепочка, если она импортирована) |
| `server.key` | закрытый ключ сервера; никому его не передавайте |
| `tls.json` | отпечатки, срок действия, источник |

Журналы сервера пишутся в подкаталог `logs/` по дням: `logs/openncalayer.YYYY-MM-DD.log`.

## Выпуск: `openncalayer tls init`

```sh
openncalayer tls init
```

Команда:
1. выпускает CA и сертификат сервера;
2. сохраняет их в `tls/`;
3. печатает инструкцию для вашей ОС: пути к файлам, отпечатки SHA-1 и SHA-256 сертификата CA, команды установки и удаления, дату, до которой нужно перевыпустить сертификат.

Если TLS уже настроен, `tls init` ничего не меняет и подсказывает `--force` (см. «Перевыпуск»).

Пока TLS не настроен, `openncalayer run` не запускается и завершается с кодом 2 и сообщением `TLS не настроен: выполните openncalayer tls init`. С флагом `--allow-no-wss` (так демон запускает relay расширения браузера) любая ошибка запуска wss — TLS не настроен или повреждён, порт занят или не открывается — не останавливает демон: он пишет предупреждение в журнал и работает только для расширения.

Состояние сертификата показывает `openncalayer tls status`: каталог, источник, отпечатки, срок действия, сколько дней осталось до перевыпуска.

## Установка CA

Ниже те же шаги, что печатает `tls init`. Перед установкой сверяйте отпечаток: он напечатан в выводе `tls init` и `tls status`.

### Windows 10 и 11

Способ 1 — командная строка, права администратора не нужны:

```bat
certutil -user -addstore Root "%APPDATA%\OpenNCALayer\tls\OpenNCALayer-CA.cer"
```

Способ 2 — оснастка «Сертификаты»:
1. Нажмите Win+R, введите `certmgr.msc` и нажмите Enter.
2. Откройте «Доверенные корневые центры сертификации» → «Сертификаты».
3. Меню «Действие» → «Все задачи» → «Импорт…». Выберите файл `OpenNCALayer-CA.cer` и хранилище «Доверенные корневые центры сертификации».

В обоих случаях Windows покажет окно «Предупреждение системы безопасности» («Security Warning») с вопросом об установке сертификата. Нажимайте «Да», только если отпечаток (sha1) в этом окне совпадает с напечатанным.

Браузеры:
- Chrome и Edge берут сертификаты из хранилища Windows;
- Firefox 120 и новее тоже доверяет ему автоматически;
- в Firefox ESR 115 включите в `about:config` параметр `security.enterprise_roots.enabled = true` или импортируйте `OpenNCALayer-CA.crt` так, как описано в разделе «Firefox вручную».

### macOS

Способ 1 — Терминал (система запросит пароль пользователя):

```sh
security add-trusted-cert -r trustRoot -p ssl -k ~/Library/Keychains/login.keychain-db \
  "$HOME/Library/Application Support/OpenNCALayer/tls/OpenNCALayer-CA.crt"
```

Способ 2 — «Связка ключей»:
1. Откройте «Связку ключей», выберите связку «login» и перетащите в окно файл `OpenNCALayer-CA.crt` (или «Файл» → «Импортировать объекты…»).
2. Дважды щёлкните сертификат «OpenNCALayer Local CA …» и сверьте отпечаток SHA-1. Раскройте «Доверие» и для «SSL» выберите «Всегда доверять».

Safari и Chrome берут сертификаты из «Связки ключей». Firefox 120 и новее тоже доверяет ей автоматически; для Firefox ESR 115 — как в разделе Windows.

### Linux

У Linux нет общего хранилища, которому верят все браузеры: CA устанавливается в каждый браузер отдельно.

Chrome и Chromium: откройте `chrome://certificate-manager` → «Свои» → «Установленные вами» → «Импортировать» и выберите `OpenNCALayer-CA.crt`.

Firefox: см. «Firefox вручную».

Или командой `certutil` из пакета `libnss3-tools` (Debian, Ubuntu) или `nss-tools` (Fedora). Браузер перед этим закройте.

```sh
certutil -d sql:<nssdb> -A -t "C,," -n "OpenNCALayer Local CA" \
  -i "${XDG_DATA_HOME:-$HOME/.local/share}/openncalayer/tls/OpenNCALayer-CA.crt"
```

Здесь `<nssdb>`:
- для Chrome и Chromium — `$HOME/.pki/nssdb`;
- для Firefox — каталог профиля `~/.mozilla/firefox/<профиль>`;
- для Firefox из snap — `~/snap/firefox/common/.mozilla/firefox/<профиль>`.

### Firefox вручную

«Настройки» → «Приватность и защита» → «Сертификаты» → «Просмотр сертификатов» → «Центры сертификации» → «Импортировать…». Выберите `OpenNCALayer-CA.crt` и отметьте флажок «Доверять при идентификации веб-сайтов».

## Проверка

1. Запустите `openncalayer run`. Если порт 13579 занят (например, запущен оригинальный NCALayer), сервер завершится с кодом 3 и сообщением `Порт 13579 занят`. Если OpenNCALayer с тем же каталогом данных уже запущен в этом сеансе, второй экземпляр завершится с кодом 4 и сообщением `OpenNCALayer уже запущен`.
2. Перезапустите браузер.
3. Откройте `https://127.0.0.1:13579/`. Страница самопроверки должна открыться **без предупреждения о сертификате** и показать «работает (приветствие и heartbeat получены)».
4. Подпись можно попробовать на демо-странице `https://127.0.0.1:13579/demo/`. Она работает через ncalayer-js-client, как обычные сайты.

Если браузер предупреждает о сертификате:
- проверьте, что CA установлен туда, откуда его читает этот браузер (см. выше);
- сверьте отпечаток в браузере с `openncalayer tls status`;
- после `tls init --force` установите **новый** CA: старый к новому сертификату сервера не подходит.

Chrome 147 и новее может спросить разрешение на доступ к локальной сети (Local Network Access), когда обычный сайт подключается к `127.0.0.1`. Разрешите его для этого сайта. Страницы самопроверки и демо открываются с самого `127.0.0.1` и такого вопроса не вызывают.

## Удаление

Windows:

```bat
certutil -user -delstore Root <SHA-1 отпечаток без пробелов>
```

Или в `certmgr.msc` удалите «OpenNCALayer Local CA …» из «Доверенных корневых центров сертификации».

macOS:

```sh
security delete-certificate -Z <SHA-1 отпечаток> ~/Library/Keychains/login.keychain-db
```

Или удалите «OpenNCALayer Local CA …» в «Связке ключей».

Linux:

```sh
certutil -d sql:<nssdb> -D -n "OpenNCALayer Local CA"
```

Или удалите «OpenNCALayer Local CA …» в `chrome://certificate-manager` («Свои» → «Установленные вами»).

Если CA импортировался в Firefox вручную, удалите его и там: «Центры сертификации» → «Удалить или не доверять».

Каталог `tls/` после удаления CA можно стереть: при следующем `tls init` всё выпустится заново.

## Перевыпуск

Сертификат сервера действует 800 дней: это меньше предела Apple в 825 дней. Перевыпускайте его заранее, за 60 дней до окончания срока. Дата перевыпуска печатается в `tls init` и `tls status`.

```sh
openncalayer tls init --force
```

Команда выпускает **новый** CA и новый сертификат сервера, затем печатает:
- отпечаток прежнего CA с просьбой удалить его из хранилищ доверия;
- инструкцию по установке нового CA.

После перевыпуска:
1. удалите старый CA (раздел «Удаление»);
2. установите новый;
3. перезапустите `openncalayer run` и браузер.

`--force` также чинит повреждённый `tls.json`.

## Свой сертификат: `openncalayer tls import`

Если у вас уже есть сертификат для `127.0.0.1`, выпущенный центром сертификации, которому доверяют ваши браузеры (например, mkcert или CA организации), подключите его вместо локального CA:

```sh
openncalayer tls import --chain server-chain.pem --key server-key.pem
```

- `--chain` — PEM-цепочка, сертификат сервера первым;
- `--key` — закрытый ключ этого сертификата в PEM.

Сертификат сервера принимается, если:
- в subjectAltName есть IP-адрес `127.0.0.1`;
- в extendedKeyUsage есть serverAuth;
- ключ — ECDSA P-256/P-384 или RSA не короче 2048 бит, и он подходит к сертификату;
- цепочка не подписана SHA-1;
- срок действия не истёк.

Собственный CA в этом случае не выпускается, и ничего устанавливать не нужно: доверие к вашему CA настраивается по правилам вашей организации. Если сертификат действует дольше 825 дней, команда предупредит: браузеры Apple такой сертификат не примут. Перевыпуск такого сертификата — повторный `tls import` с новыми файлами.
