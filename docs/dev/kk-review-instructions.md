# Инструкция для проверяющего казахских текстов

Для человека, который читает казахский текст OpenNCALayer **как носитель языка**. Выбирает его владелец проекта. Ни одна казахская строка не вычитана носителем; таблица [`kk-native-review.md`](kk-native-review.md) имеет для всех 34 строк статус `needs native review`. Этот документ — лист для проверяющего (раздел 4), способ увидеть каждую строку в программе (раздел 2) и вопросы терминологии, на которые нужно ответить (раздел 3).

Править казахские строки в исходном коде должен тот, кто принимает правки (ассистент после вашего согласия): проверяющий их не меняет, а заполняет колонки «Исправленный kk» и «Комментарий». Этот документ казахские строки **не** меняет.

## 1. Что такое OpenNCALayer (для понимания контекста)

Программа для подписи документов электронной цифровой подписью (ЭЦП) на компьютере пользователя: аналог NCALayer, на который опираются веб-сайты государственных и коммерческих сервисов Казахстана. Живёт значком в области уведомлений. Сайт просит программу подписать документ ключом из файла хранилища ключей (PKCS#12, JKS) или с носителя (токен, удостоверение); программа показывает окно, пользователь выбирает ключ, вводит пароль, видит, **что именно** будет подписано, и подтверждает.

Для вас важнее следующее. В версии alpha.7 появилась страница «Плагины» окна «Инструменты…»: пользователь сам выбирает операцию плагина (подписать файл или текст), свой ключ и видит **страницу подтверждения** — единственное место, где он разрешает использовать ключ. Тексты этой страницы, страницы результата, окна установки плагина и справки на первой странице окна «Инструменты» — предмет проверки. Они юридически и практически важны: пользователь решает, подписывать ли, по этим словам. Поэтому ищите не только ошибки языка, но и места, где формулировка **меняет смысл** или звучит неоднозначно (например, «подписывается» вместо «будет подписан один раз»; «рұқсат» в смысле «разрешение» и «согласие» ).

Пояснение терминов: **ключ** — закрытый ключ ЭЦП; **сертификат** — сертификат открытого ключа; **хранилище ключей** — файл с ключом и сертификатом; **плагин** — дополнительный модуль, который выполняет подпись по правилам конкретного сервиса; **хеш/дайджест** — число-отпечаток файла; **XPath** — адрес элемента в XML-документе; **канонизация** — приведение XML к стандартному виду перед подписью.

## 2. Как увидеть строки в программе

Нужны Windows и программа alpha.7 (или сборка владельца). Не используйте ваши настоящие ключи для проверки текстов: подписывать ничего не нужно, достаточно дойти до нужной страницы и **не нажимать** кнопку «Подписать плагином…».

1. Установить программу (установщик `openncalayer-0.1.0-alpha.7-win-x64-setup.exe`).
2. Задать казахский язык. Язык окон и значка — ключ `locale` в файле `settings.json` каталога данных (`%APPDATA%\OpenNCALayer\settings.json`; значения `ru`, `kk`, `en`; `README.md`, раздел про `settings.json`). Пример содержимого: `{"locale": "kk"}`. Перезапустить программу. Окно «Настройки…» из меню значка тоже содержит выбор языка.
3. Открыть окно: меню значка → «Инструменты…» (или команда `openncalayer tools`). Левый список: «Обзор», «Подписать», «Проверка», «Продление», «Извлечение», «Метка времени», «Хеш», «Сведения», «Плагины» (в казахском интерфейсе — «Плагиндер»).
4. Для страниц плагинов нужен плагин с операциями. До выпуска плагинов (MP11) их можно поставить из файла: владелец или ассистент соберёт пакеты (`cargo xtask plugin pack plugins/<порт>` → `target/plugins/<id>-<версия>.onclp`) и даст вам `.onclp`. «Плагины…» → «Установить из файла…». Проверять удобно на плагинах:
   - `energy` → `sign-cms-detached` (файл): страница подтверждения, `c_prehash`, строки вида подписи;
   - `rating1c` → `sign-xml-element` или `eproc` → `sign-xml-element`: строки XPath (`c_role_element`, `c_role_parent`), преобразования (`xml_transforms`, `tr_*`), пересериализация (`xml_serialized`);
   - `qiwi` → `sign-xml-rsa`: название операции (метка операции), `binding` (привязка пространств имён) в окне установки.
5. Дойти до нужного места (колонка «Где показано» листа) и сделать скриншот. Для страницы подтверждения нужен ключ: любое **тестовое** хранилище `.p12` (владелец даст синтетическое `fixtures/synthetic/user-rsa-sign.p12`, пароль записан в `fixtures/synthetic/fixtures.toml`, запись `user-rsa-sign`; настоящий ключ не используйте). Дальше «Показать, что будет разрешено» — и вы на странице подтверждения. Кнопку «Подписать плагином …» **не нажимайте**; «Отмена».
6. Некоторые строки штатно не воспроизводятся (отказы плагина, особые ошибки): в листе помечено «оценивать как текст».

Единственная строка, где источник не в окне: `Hash help` (справка на странице «Обзор»), она показана сразу после запуска «Инструменты…».

Заполненный лист возвращается владельцу проекта. Названия операций — слова автора плагина и пакеты версий плагинов, поэтому правка названий требует нового выпуска пакета с поднятием версии порта.
