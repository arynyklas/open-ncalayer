# Манифесты WinGet: генерация, проверка установки и подача

Инструкция мейнтейнера. Установщик, который WinGet запускает, описан в [`winget-installer.md`](winget-installer.md); здесь — как из опубликованного релиза получить манифест, что должно быть доказано до него и как его подать в `microsoft/winget-pkgs`.

## Состояние (читать первым)

**OpenNCALayer в WinGet недоступен.** Команда `winget install --id arynyklas.OpenNCALayer --exact` — целевой сценарий, а не существующая функция. Сделано и проверено локально: генератор и проверяющий манифестов (`cargo xtask winget`), типизированный отчёт о проверке установки, скрипты матрицы ВМ, workflow только для чтения, эта процедура. Состояние после этого — «готова локальная подача, ожидаются внешние условия»; оно меняется только по пунктам ниже.

Внешние предпосылки (ни одна не выполнена на момент написания):

| # | Что нужно | Почему нельзя обойти |
|---|---|---|
| 1 | **Опубликованный stable-релиз** (`v<major>.<minor>.<patch>`, не черновик, не pre-release) с подписанными Authenticode `…-win-x64-winget-setup.exe` и `…-win-x86-winget-setup.exe` | Последние теги — alpha. Генератор отвергает alpha/beta, черновики и изменяемые URL; переименовывать alpha в stable нельзя. |
| 2 | **Подпись SignPath настроена** (шаг оператора из `winget-installer.md`) | Файл без Authenticode не получает манифест; отчёт «unsigned» отвергается. |
| 3 | **Матрица чистых ВМ пройдена** на опубликованных байтах (раздел «Проверка установки») | Схема и YAML ничего не говорят о том, что установщик ставит, обновляет и удаляется. |
| 4 | **Свободен `PackageIdentifier`** `arynyklas.OpenNCALayer` в `microsoft/winget-pkgs` | Проверяется перед подачей руками; генератор идентификатор не резервирует. |
| 5 | **Отдельная команда владельца проекта** на первый fork/коммит/PR | Ничего из этого не делается ни скриптом, ни workflow, ни агентом. |
| 6 | **Решение Microsoft** (валидация и слияние) и индексация | Принятие не гарантировано. |

## Порядок работы

```text
stable-релиз ──► cargo xtask winget candidate ──► (ВМ) scripts/winget/Invoke-WingetProbe.ps1 × 8 ячеек
                                                        │
                      Merge-ProbeCells.ps1 ◄────────────┘
                                │
                                ▼
      cargo xtask winget generate ──► cargo xtask winget check ──► winget validate ──► подача (раздел ниже)
```

### 1. Кандидат

```sh
gh api repos/arynyklas/open-ncalayer/releases/tags/v<версия> > release.json
cargo xtask winget candidate --release-json release.json --out target/winget-candidate
```

Команда читает релиз GitHub API и отказывает, если он не опубликован как stable (таблица ниже). Затем **один раз** скачивает каждый из двух установщиков по URL вида `https://github.com/arynyklas/open-ncalayer/releases/download/v<версия>/<файл>` (только HTTPS, только публичные адреса, предел 512 МиБ), по этому же потоку считает SHA-256 и размер и сверяет их с `size` и `digest` из API; проверяет, что файл — установщик этой версии и архитектуры (полезная нагрузка читается так же, как её читает сам установщик, `oncl-winget-setup::payload::read`) и что у него есть таблица сертификатов Authenticode. Результат — каталог с тремя файлами (`arynyklas.OpenNCALayer.yaml`, `….locale.en-US.yaml`, `….installer.yaml`) и `target/winget-candidate.evidence.json`.

Кандидат — **вход проверки установки**, а не манифест для подачи: в нём нет сопоставления Apps & Features (его ещё не знает никто, кроме реальной установки), и `cargo xtask winget check` без `--candidate` его отвергает. Кандидат — чистая функция релиза и скачанных байт: повторный запуск даёт тот же `installer.yaml` побайтно, и его SHA-256 записан в отчёте проверки.

См. раздел ниже: восемь ячеек матрицы, каждая — один запуск скрипта внутри ВМ.

### 3. Итоговый манифест

```sh
pwsh scripts/winget/Merge-ProbeCells.ps1 -Cells ./cells/*.json -FinalCells ./final/*.json -AttestedBy <имя> -RunId <идентификатор> -OutFile winget/probes/<версия>.json
cargo xtask winget generate --release-json release.json --probe winget/probes/<версия>.json --out target/winget
cargo xtask winget check target/winget
winget validate target/winget
```

`generate` заново скачивает установщики (одним потоком каждый) и принимает отчёты только если **каждое** утверждение выполняется для именно этих байт (раздел «Что отвергается»). Каталог вывода должен быть новым или пустым; рядом пишется `target/winget.evidence.json` (хеши, размеры, `"submitted": false`, готовая запись для реестра хешей). `check` — схемы 1.12.0 и инварианты пакета; `winget validate` — настоящий парсер WinGet. Это проверка схемы, а не установки.

Файл `winget/probes/<версия>.json` коммитится в ветку по умолчанию **до** запуска workflow (он читает его оттуда; в PR подачи он ссылается как на свидетельство): это свидетельство, из которого сделан манифест. Скачивание следует только по HTTPS и только на github.com / *.githubusercontent.com, в том числе при перенаправлениях. `check` не принимает каталог, в заголовке которого написано NOT FOR SUBMISSION. В них нет путей машин и имён пользователей (отчёт хранит только версии, хеши, коды и признаки); если в отчёт попало лишнее, `cargo xtask privacy` остановит коммит.

## Что отвергается

| Вход | Причина |
|---|---|
| Черновик; `prerelease: true`; тег не `v<major>.<minor>.<patch>` (alpha, beta, `+build`, `latest`); нет `published_at` | Нужен опубликованный stable. Флаг, снятый с alpha, не помогает: проверяется и тег. |
| `browser_download_url` не равен `https://github.com/arynyklas/open-ncalayer/releases/download/v<версия>/<файл>` | `latest/download`, другой репозиторий, другой тег, `http`, строка запроса — изменяемые или чужие URL. |
| Установщик другой версии или флейвора (`win7-*`, `arm64`, чужой номер) среди ассетов; нет одного из двух; дубликат; не `uploaded`; нулевой размер; `digest` не `sha256:<64 hex>` | Чужой или неподходящий ассет. До скачивания ничего не качается. |
| Размер или `digest` из API ≠ байты потока | Подмена или обрыв. API — ожидаемое значение, фактическое даёт поток. |
| Файл не PE нужной архитектуры, нет полезной нагрузки `Setup` этой версии и архитектуры, нет таблицы сертификатов | Не тот файл, не тот флейвор, не подписан. |
| Версия уже есть в `winget/hash-ledger.json` с другим хешем | Опубликованная версия не получает другой установщик: выпускается новая версия. |
| Отчёт: поля нет или лишнее; `origin: synthetic-fixture` | Не доказано; синтетические данные принимает только тест. |
| Отчёт: хеш, размер, имя, URL, версия не совпадают с опубликованным; время записи раньше публикации | Проверялся не этот файл. |
| Отчёт: подпись не `valid`, нет подписанта, отпечатка или метки времени | Authenticode не доказан. |
| Отчёт: переключатели, с которыми WinGet запустил установщик, не ровно `["--silent"]` (и для silent, и для silent-with-progress), или у WinGet были флаги вне списка (`--force`, `--ignore-security-hash`, `--override`, `--custom`…) | Допускается только проверенный `--silent`, не общий `/S` других установщиков. |
| Отчёт: `installer.yaml` ячейки не равен кандидату этого релиза | Установка шла не из того манифеста. |
| Отчёт: `DisplayVersion`, `--version` программы, версия манифеста установки ≠ версия пакета; пустые ключ, имя, издатель; ячейки спорят об идентичности; размещение не в профиле учётной записи; деинсталлятор не `Update.exe` установки | Сопоставление Apps & Features не доказано. |
| Отчёт: нет «без пререквизитов» (чистый образ без Visual C++, установка без шага пререквизита) | Установщик не самодостаточен. |
| Отчёт: состояние установки не осмотрено после завершения процессов, коды ≠ 0, версии после выхода не те | Код возврата без проверки результата ничего не доказывает (`Setup.exe` Velopack при невыполненных условиях выходит с 0). |
| Отчёт: upgrade не от более старой версии, потеряны данные пользователя, uninstall оставил запись или каталог, self-update ушёл назад или WinGet предлагает понижение | Жизненный цикл не доказан. |
| Отчёт: повышенный запуск не завершился кодом 8 до записи, активная подпись не удержана кодом 4 с неповреждённым результатом, добавлен корневой сертификат, появился слушатель вне loopback | Нарушены свойства безопасности из задачи. |
| Матрица неполна (раздел ниже) | Нет доказательства для части ячеек. |

## Манифест

Идентификатор `arynyklas.OpenNCALayer`; три файла схемы 1.12.0 (`version`, `defaultLocale` — `en-US`, `installer`); два установщика, `x64` и `x86`, `InstallerType: exe`, `Scope: user`, `ElevationRequirement: elevationProhibited`, `MinimumOSVersion: 10.0.17763.0` (Windows 10 1809), `Silent` и `SilentWithProgress` — `--silent` (режима `Interactive` у входа нет: `winget install --interactive` запускает его без `--silent`, и он отказывает), `UpgradeBehavior: install` и `RequireExplicitUpgrade: true` (явное `winget upgrade` поддержано, `upgrade --all` пакет не трогает; штатный updater программы сохраняется), `uninstallPrevious` и `deny` не подставляются. `InstallerSuccessCodes` не расширяется; код 4 (занято: подпись в работе) описан как `ExpectedReturnCodes → packageInUse`, то есть ответ, а не успех. `AppsAndFeaturesEntries` и `PackageVersion` берутся из реального сопоставления отчёта; `InstallerSha256` — только из хеша потока окончательно опубликованного и подписанного файла.

Проверка (`cargo xtask winget check`): закреплённые схемы `xtask/assets/winget/schema-1.12.0/` (из `microsoft/winget-cli`, SHA-256 закреплены в `xtask/src/winget/schema.rs`; валидатор знает только ключевые слова этих схем и на любое другое отказывает, лишние ключи в манифесте — ошибка, хотя схема их допускает), затем инварианты пакета: те же поля, URL именно этой версии, ровно два установщика, никаких непроверенных переключателей, `DisplayVersion` равен `PackageVersion`, в каталоге ровно три файла.

## Проверка установки (матрица ВМ)

Выполняется **после** публикации релиза, на опубликованных байтах. Нужны чистые образы (снимок до всяких установок, без Visual C++ Redistributable, без OpenNCALayer), `winget` с включённой настройкой локальных манифестов (`winget settings --enable LocalManifestFiles`, один раз при подготовке образа, только внутри ВМ; настройки хоста не менять), доступ в сеть до `github.com` и более старый обычный установщик `openncalayer-<старая версия>-win-<арх>-setup.exe` для проверки обновления.

Ячейки (по одному запуску `Invoke-WingetProbe.ps1`; генератор требует именно этот охват), всего восемь:

| Установщик | Образ ВМ | Учётные записи |
|---|---|---|
| x64 | Windows 10 x64 | стандартная; администратор без повышения |
| x64 | Windows 11 x64 | стандартная; администратор без повышения |
| x86 | Windows 10 **x86** (32-битная) | стандартная; администратор без повышения |
| x86 | Windows 11 x64 (WOW64; 32-битной Windows 11 нет) | стандартная; администратор без повышения |

Генератор проверяет охват: для каждой пары «установщик × тип учётной записи» есть ячейка Windows 10 и ячейка Windows 11, для x86 — ещё и 32-битная система для обоих типов; x64-установщик на 32-битной системе не принимается. Лишние ячейки (другие сборки Windows) допустимы.

В ВМ, от имени проверяемой учётной записи, **без повышения** (скрипт откажется работать на повышенном токене, не в ВМ или Sandbox, и на образе, где уже стоит программа):

```powershell
.\Invoke-WingetProbe.ps1 -ManifestDir .\candidate -InstallerArch x64 -Tag v<версия> `
    -OldSetup .\old\openncalayer-<старая>-win-x64-setup.exe -OldVersion <старая> `
    -Account standard -OtherAdminProfile (Join-Path $env:SystemDrive 'Users\<админ>') `
    -CleanImageAttested -OutFile .\cell-x64-win10-standard.json
```

Что делает скрипт и что он записывает в отчёт (поля отчёта — типизированная структура `InstallerProbeReport` в `xtask/src/winget/probe.rs`):

1. **Среда**: сборка Windows, архитектура, тип учётной записи (стандартная / администратор с неповышенным токеном — сверка с `-Account`), ВМ или Sandbox, чистый образ без Visual C++ (`-CleanImageAttested` — подтверждение оператора, что образ из чистого снимка), SID: `HKCU` и `%LOCALAPPDATA%` принадлежат профилю этой учётной записи.
2. **Опубликованный файл**: скачивается один раз по URL релиза; SHA-256, размер, `Get-AuthenticodeSignature` (статус, подписант, отпечаток, метка времени); хеш сверяется с кандидатом.
3. **Повышенный запуск** (оператор подтверждает запрос UAC; стандартной учётной записи UAC спрашивает учётные данные администратора — это проверка «других credentials»): код 8, ничего не записано ни в свой профиль, ни в профиль `-OtherAdminProfile`, ни в профиль SYSTEM, ни в HKLM.
4. **`winget install --manifest <каталог> --silent`**: какими аргументами WinGet запустил установщик, снимается наблюдением за командной строкой дочернего процесса (если процесс не пойман, ячейка падает, а не угадывает); затем, **после завершения и WinGet, и установщика**, смотрится сама установка: запись Apps & Features (ключ, имя, издатель, версия), `openncalayer --version`, манифест установки `current\sq.version`, архитектура программы, расположение в профиле и владелец, деинсталлятор — `Update.exe` установки.
5. **Тот же без флага режима** (`SilentWithProgress`), после удаления: повторная установка — это `reinstall`.
6. **Upgrade** со старой версии, установленной её обычным установщиком; контрольный файл в `%APPDATA%\OpenNCALayer` должен пережить обновление без изменений. **Удержание подписи** (оператор): запустить долгую подпись в работающей программе, `winget upgrade` обязан вернуть код 4 установщика, подпись — завершиться корректно (ответ оператора), установка — остаться прежней; затем upgrade без активных операций.
7. **Self-update**: если есть более новый релиз, скрипт ждёт `-SelfUpdateTargetVersion` (оператор вызывает «Проверить обновления» в меню значка), и WinGet после этого не предлагает понижения или переустановки. **Пока более нового релиза нет, самообновление до него не может быть проверено**: отчёт тогда фиксирует отсутствие понижения при неизменной версии, а полная проверка выпадает на следующий релиз. Это известный предел, не результат.
8. **Безопасность**: после установки ни один корневой сертификат не добавлен (пользователь и компьютер), у процессов программы нет слушателей вне loopback и нет `oncl-server.exe`; затем `winget uninstall`.

Подтверждения оператора (шаги 3 — UAC, 6 — подпись и её итог, 7 — запуск проверки обновлений) записываются в отчёт как наблюдения; скрипт их не имитирует.

Список из `winget-installer.md` (пункты 1–6 и «Дополнения к списку ВМ») остаётся чеклистом: к нему добавляются перезапуск ВМ после upgrade, одновременный штатный updater, открытое окно подтверждения, ручные инструменты и вызов плагина во время установки, установка поверх alpha.6 без endpoint (код 5). Они наблюдаются руками и в машинный отчёт не входят: отчёт — минимум, без которого манифест не делается.

Скрипты кладут по одному JSON на ячейку; `Merge-ProbeCells.ps1` собирает набор (`vm-run`, а при синтетической ячейке — `synthetic-fixture`; `-PendingFinal` — набор без ячеек итогового манифеста, только для `generate --final-proof-pending`). Итоговый каталог в ВМ ставит `Invoke-WingetFinalProbe.ps1` (раздел ниже); он обязателен.

## Что значит отчёт и чего он не доказывает

Отчёт — **заверение оператора** (`attestation.attested_by`, `run_id`): генератор проверяет согласованность ячеек с опубликованными байтами (хеш, размер, URL, версия), друг с другом (одна идентичность Apps & Features, один `script_sha256` у всех ячеек, `vm_id` у каждой) и с кандидатом; он не видит машин. Скрипты ставят `synthetic: false`; `Merge-ProbeCells.ps1` помечает весь набор `synthetic-fixture`, если хоть одна ячейка синтетическая, а генератор такой набор для итогового манифеста не принимает (набор `vm-run` с синтетической ячейкой тоже). Authenticode: генератор видит только наличие таблицы сертификатов; цепочку проверяет ВМ.

## Архитектура установщика и итоговый манифест в матрице

Скрипты передают `winget install/upgrade --architecture <x64|x86>` (документированная опция WinGet): без неё на x64 Windows WinGet выбрал бы x64-установщик, и ячейка x86 × Windows 11 была бы невозможна. В отчёт идёт `winget_architecture`, он обязан совпасть с установщиком; из флагов добавлен ровно `--architecture`.

Основные ячейки идут по **кандидату**; затем `Invoke-WingetFinalProbe.ps1` (минимум одна ячейка на архитектуру) ставит, обновляет старую установку и удаляет по **итоговому** каталогу (с `AppsAndFeaturesEntries`): генератор требует `final_cells`, чей `installer.yaml` совпадает с генерируемым, upgrade нашёл и обновил старую запись, uninstall её убрал. Каталог для этих ячеек делается до их появления: `cargo xtask winget generate … --final-proof-pending` (файлы те же байты, что в полном запуске; в `evidence` — NOT READY, подавать нельзя); после ячеек `generate` повторяется без флага.

## Самообновление и вердикт (`status.json`)

`newer_release_tested: true` допустимо только если программа сама поставила более новый релиз: тогда `arp_display_version` выше `start_version`, и наоборот (признак и версии сверяются в обе стороны). `no_downgrade_loop` требует, чтобы `winget upgrade --manifest` не запускал установщик и вернул «нет применимого обновления» (0x8A15002B). Список релизов генератору не передаётся: сверка идёт по версиям в отчёте.

Рядом с каталогом манифеста (не внутри: `winget validate` должен видеть только файлы манифеста) пишется `<каталог>.status.json` с вердиктом, причинами, записанным отказом и `manifest_files_sha256` — одним хешем всех трёх файлов; его же должны нести ячейки итогового манифеста. Вердикт печатают `generate` и `check --for-submission`, он попадает в сводку workflow:

| Вердикт | Когда |
|---|---|
| `ready` | Все доказательства, включая самообновление до более нового релиза. |
| `submittable-with-waiver` | Доказано всё, кроме самообновления, и в отчёте записан `waiver` `{reason, approved_by, date}`. Генератор его никогда не придумывает; без него вердикт `not-ready`. |
| `not-ready` | Всё остальное: кандидат, синтетика, `--final-proof-pending`, нет доказательства самообновления без отказа. |

Первый stable-релиз не может быть `ready` (новее него ничего нет). Принимать ли отказ от самообновления для него — **решение владельца проекта**, не агента и не скрипта. Каталог со статусом `not-ready` подавать нельзя: байты такого каталога совпадают с готовым, поэтому проверяйте `cargo xtask winget check --for-submission <каталог> --release-json <release.json> --probe <probe.json>`: он **пересчитывает** вердикт из этих входов (заново скачивает установщики и проходит весь `generate` во временный каталог) и падает без статуса, при несовпадении файлов, хешей входов (`release_sha256`, `probe_sha256` в `status.json`) или вердикта и при `not-ready`. `status.json` не подписан: это защита от случайной подачи, а не от того, у кого есть доступ на запись во входы; отчёт ячеек остаётся заверением оператора.

## Реестр хешей и повторная генерация

`winget/hash-ledger.json` (допустимый пустой вид — `{"versions": {}}`; отсутствующий, пустой файл или `{}` — ошибка; проверяется при чтении: версия `<major>.<minor>.<patch>`, ключи ровно `x64` и `x86`, SHA-256 строчными; отсутствующий или пустой файл — ошибка; это защита от случайной замены, а не граница безопасности: кто может пушить, тот может его править) — версии, уже поданные в WinGet, и хеши их установщиков. В момент подачи в него коммитится `ledger_entry` из `target/winget.evidence.json`; с этого момента `generate` для той же версии с другим хешем отказывает. Ассет релиза, заменённый после подачи, — повод выпустить новую версию, а не пересчитать манифест.

## Workflow `winget.yml`

`.github/workflows/winget.yml` запускается по завершении workflow `Release` (событие `release` для релиза, созданного `GITHUB_TOKEN`, другие workflow не запускает, поэтому, как и `aur.yml`, он следит за `workflow_run`; тег — `head_branch`, не-stable тег пропускается с notice) или вручную с тегом; права `contents: read`, без секретов и токенов с записью, без fork и PR. Он делает шаги 1 и 3 для тега: кандидат (артефакт) и, если в репозитории есть `winget/probes/<версия>.json`, итоговый манифест с проверкой; `winget validate` — если `winget` есть на раннере (иначе предупреждение, что он **не** запускался). Без отчётов ячеек пишет «PENDING» и итогового манифеста не делает. Зелёный запуск ничего не публикует.

## Подача в `microsoft/winget-pkgs`

Только после пунктов 1–4 таблицы предпосылок, при вердикте `ready` или `submittable-with-waiver` с записанным отказом (`check --for-submission`) и **только по отдельной команде владельца проекта**. Ничего из этого раздела не выполняется автоматически, и до слияния Microsoft состояние остаётся «готова локальная подача / ожидается внешнее разрешение».

1. **Уникальность и свидетельства.** `winget search arynyklas`, `winget search OpenNCALayer`; в `microsoft/winget-pkgs` нет каталога `manifests/a/arynyklas/OpenNCALayer/` и нет открытых PR/issues с этим идентификатором; издатель `arynyklas` соответствует аккаунту. Записать результат. Ещё раз `cargo xtask winget generate` (заново скачать байты и убедиться, что хеши те же), `check`, `winget validate`.
2. **Fork и ветка** (первое внешнее действие, по команде): fork `microsoft/winget-pkgs`, ветка `arynyklas.OpenNCALayer-<версия>`.
3. **Файлы**: скопировать три файла из `target/winget/` в `manifests/a/arynyklas/OpenNCALayer/<версия>/`. Имена файлов и версия каталога — как в манифесте; другие файлы в каталоге не нужны.
4. **Проверки до PR**: `winget validate --manifest manifests/a/arynyklas/OpenNCALayer/<версия>`; в ВМ или Sandbox `winget install --manifest <каталог> --silent`, затем `winget uninstall`. Флаги `--force` и `--ignore-security-hash` не использовать.
5. **Коммит и PR** с заголовком `New package: arynyklas.OpenNCALayer version <версия>`, шаблон PR заполнить честно (проверки отмечать только выполненные). В тот же момент закоммитить запись в `winget/hash-ledger.json` и отчёт `winget/probes/<версия>.json`.
6. **Валидация Microsoft.** Конвейер репозитория проверяет манифест (схема, URL, хеш, скачивание, установка в Sandbox, антивирус, политики), боты отвечают комментариями и метками; ответить на замечания, при смене манифеста — заново `check` и `validate`. Решение и сроки не гарантируются. Если нужно исправить манифест, а установщик остался прежним, правка идёт в том же PR; если менялись байты установщика — новая версия.
7. **После слияния** и индексации источника (может занять часы) — отдельно, в **чистой** ВМ: `winget show arynyklas.OpenNCALayer`, `winget install --id arynyklas.OpenNCALayer --exact --source winget --silent`, upgrade и uninstall, как в матрице. Только после этого README можно переписать с «планируется» на «доступно», и только для проверенной версии.

## Что не доказано (на момент написания)

- Реальный stable-релиз, реальные ВМ и реальная установка через WinGet не выполнялись: тесты `xtask/tests/winget.rs` используют **синтетические** данные (JSON «релиза», минимальные PE-образы с полезной нагрузкой в формате входа, отчёты, составленные тестом) и помечены как синтетические; скачивание идёт настоящим клиентом с локального сервера. Настоящий `winget validate` прогоняется отдельным тестом `real_winget_validates_the_emitted_manifests` (`-- --ignored`) на синтетическом манифесте; это проверка схемы.
- Скрипты `Invoke-WingetProbe.ps1` внутри ВМ не запускались (они разбираются парсером PowerShell, а `Merge-ProbeCells.ps1` исполняется тестом и читается Rust-структурой); их первая настоящая работа — первая матрица, и она может найти ошибки скрипта, которые придётся исправить до записи отчёта.
- Authenticode проверяет ВМ (`Get-AuthenticodeSignature`); генератор проверяет только наличие таблицы сертификатов, не цепочку и не отпечаток.
- Имя и издатель в Apps & Features, значение `DisplayVersion` и ключ реестра установщика Velopack известны только по первой настоящей установке; тест использует вымышленные значения.
- Коммит `efcb928b…` в `NOTICE` (последнее изменение каталога схем в winget-cli) не подтверждён вторым источником: GitHub API был недоступен рецензенту; байты схем сверены с master и закреплены хешем.
- Не сделано (отложено): закрепление подписанта (M4), флаг `immutable` релиза (M7), часть негативных тестов (M9), коммит настоящего JSON alpha в тест (M10).
