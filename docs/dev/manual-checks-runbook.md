## 1. (a) Настоящая подпись через нативное окно плагинов

### 1.1 Что подготовить

| Что | Зачем | Заметки |
|---|---|---|
| Настоящий файл хранилища ключей **PKCS#12 (`.p12`) или JKS** с паролем | страница «Плагины» принимает только их: токены и удостоверения на ней не предлагаются (`docs/user/manual-plugins.md`) | сертификат должен быть действующим, предназначенным для подписи |
| Доступ к службам НУЦ | перед применением ключа программа проверяет вашего подписанта по OCSP (`ocsp.pki.gov.kz`); метка времени — `tsp.pki.gov.kz` (только у операций «с меткой времени») | сеть только к этим узлам, окно других адресов не открывает |
| Интерактивный рабочий стол, окно которого **получает передний план** | прошлый прогон «en 200 %» закончился `focused=False` из-за отсутствия переднего плана (`fg pid 0`); smoke 2026-11-07 выполнялся в RDP-сеансе `Active` | не блокировать экран и не сворачивать сеанс во время подписи |
| Ключ RSA (рекомендуется) | независимая проверка результата возможна только для RSA (OpenSSL, lxml): для ГОСТ внешнего проверяющего нет (12 строк матрицы взаимодействия BLOCKED) | если ваш ключ ГОСТ — результат сравнить можно только с собственной проверкой программы (`oncl verify`), это не независимая проверка |
| Независимый проверяющий | сверить подпись не нашим кодом | для CMS — OpenSSL (`openssl cms -verify`), для XML — любой xmldsig-проверяющий; не проверено, какая версия OpenSSL установлена у вас |
| Одноразовый каталог данных | не трогать ваши настоящие настройки, TLS и автозапуск | переменная `ONCL_DATA_DIR` (`crates/openncalayer/src/paths.rs`); сертификаты и автозапуск не менять |

### 1.2 Какая сборка

**Правильный выбор — обычная релизная сборка, без `e2e-prompter`.** Причины (по коду):

- `e2e-prompter` (`crates/openncalayer/Cargo.toml`): при `ONCL_E2E_PROMPTER=<steps.json>` команда `run` отвечает на диалоги подписи из сценария и не открывает окон; это тестовая сборка, «никогда в релизах».
- `ONCL_E2E_SIGNING_TRUST=<файл корневого сертификата>|<origin PKI>|<unix-время>` (`crates/openncalayer/src/main.rs`, `signing_trust`) существует **только** в сборке с `e2e-prompter` и подменяет цепочку доверия и часы синтетическим УЦ на loopback. Это нужно для положительной ветки на **синтетическом** ключе (smoke 2026-11-07: «успешная подпись и отчёт Valid недостижимы с релизной сборкой»), а не для настоящего ключа. Настоящий ключ проверяется релизной сборкой против национального УЦ.
- В репозитории нет готового loopback-УЦ для этой переменной: ни один тест и ни один документ её не используют (поиск по `crates/`, `xtask/`, `docs/` нашёл её только в `main.rs`). Положительная ветка на синтетической цепочке — работа ассистента при выданном доступе, не этого runbook.

Получить релизную сборку:

- **Установщик из черновика alpha.7** (тот, что пройдёт матрицу): `openncalayer-0.1.0-alpha.7-win-x64-setup.exe`. Это лучший вариант: проверяется то, что получит пользователь.
- или локально из чистого дерева на нужном коммите: `cargo build --release -p openncalayer` → `target/release/openncalayer.exe` (**[не проверено]**: именно эта команда для локального запуска; CI собирает релизные флейворы через `cargo xtask package windows`, а `cargo build --release … --features e2e-prompter` только для артефакта `conformance`).

Версия должна быть не ниже alpha.7 (`min_core` манифестов), иначе операции не появятся.

### 1.3 Какой плагин и какая операция

До выпуска плагинов (MP11) в каталоге нет пакетов с операциями (`manual-plugins-status.md`, п. 4), поэтому пакет собирается из дерева и ставится «из файла»:

```sh
cargo xtask plugin pack plugins/energy
```

Команда пишет `target/plugins/<id>-<версия>.onclp` (`release.md`, §7а). В программе: значок → «Плагины…» → «Установить из файла…» (фильтр `*.onclp`); окно предупредит, что плагина нет в каталоге, и покажет каждую операцию плагина.

Рекомендуемая пара:

1. **`energy` → `sign-cms-detached`** (файл; CMS, отделённая подпись, без метки времени). Требует только OCSP. Файл — небольшой текстовый, значительно меньше предела окна: **4 МиБ** на 64-разрядной системе (`ManualLimits::desktop()`), 512 КиБ на 32-разрядной.
2. **`rating1c` → `sign-xml`** (текст XML ≤ 65 536 знаков; подпись всего документа).

Список всех 30 операций — `docs/user/manual-plugins.md`. Для первого раза достаточно одной операции; XML — вторая проверка, если время есть.

### 1.4 Запуск и порядок действий

1. Одноразовый каталог данных, например в PowerShell: `$env:ONCL_DATA_DIR = "$env:TEMP\oncl-real-sign"; New-Item -ItemType Directory -Force $env:ONCL_DATA_DIR | Out-Null`. Все дальнейшие процессы запускать в этом же окне консоли.
2. Запустить окно инструментов: `openncalayer tools` (команда `tools` — `crates/openncalayer/src/main.rs`; если программа не запущена, она стартует с значком и без wss, `--allow-no-wss`). Установленный экземпляр: тот же `openncalayer.exe` из `%LOCALAPPDATA%\OpenNCALayer\current\` **[не проверено: точный путь каталога установки]**.
3. «Плагины…» → установить пакет из файла (п. 1.3).
4. «Инструменты…» → «Плагины» → операция → «Открыть». Форма: файл (или текст) и **хранилище ключей** (путь к `.p12`). «Продолжить» ничего не подписывает.
5. Страница «Ваш ключ»: пароль хранилища → список сертификатов → выбрать → «Показать, что будет разрешено».
6. **Страница подтверждения** — единственное место согласия. Проверьте и **запишите**: «Операция», «Плагин: <id>, версия», вид подписи, «Применений вашего ключа: 1», имя файла, размер и **SHA-256 файла** (сверить с `Get-FileHash`), владельца сертификата и **SHA-256 сертификата**. Фокус при открытии на «Отмена», Enter сам не подтверждает; кнопка действует через 0,6 с после показа. Кнопка согласия: «Подписать плагином <операция>».
7. Нажать её. Результат: «Применение ключа: выполнено / не выполнено / неизвестно». Зелёным «успехом» не называется ничто (подпись в ответе программа не проверяет).
8. Ответ плагина показан только первыми 2 000 символов; **целиком сохраняется как `.json`** (G1) только при применённом ключе и завершении плагина без ошибки. Сохраните ответ кнопкой сохранения на странице результата (английский текст: «Save the plugin reply (not verified by this program)»; русский — как в окне).

### 1.5 Сравнение с независимым проверяющим

Что сохраняет окно — весь ответ плагина как `.json`; где именно в нём подпись, программа не знает (`manual-plugins-status.md`, п. 5), и формат ответа конкретного плагина **не проверен документом**: откройте файл и найдите поле с подписью (CMS обычно в base64).

1. Извлечь подпись из ответа в файл `sig.der` (base64 → DER).
2. CMS, отделённая (RSA):

   ```sh
   openssl cms -verify -binary -inform DER -in sig.der -content <ваш файл> -noverify -out content-check.bin
   ```

   `-noverify` отключает проверку цепочки (цепочка НУЦ в доверенное хранилище OpenSSL не входит; её проверяет сама программа). Для проверки цепочки передайте корни НУЦ через `-CAfile`. Код выхода 0 и строка `CMS Verification successful` — подпись над байтами файла верна; `content-check.bin` должен совпасть с вашим файлом побайтно (`cmp`). Команда проверена на OpenSSL 3.5.4 с отсоединённой подписью DER, сделанной `openssl cms -sign -binary -outform DER` самоподписанным ключом RSA (вывод: `CMS Verification successful`, `content-check.bin` совпал с исходным файлом); на подписи плагина и сертификате НУЦ **[не проверено]**: формат ответа плагина и извлечение подписи из него здесь не описаны.
3. XML: проверить подпись xmldsig независимым инструментом. Оракул матрицы взаимодействия проверяет XML на `lxml`, `cryptography` и `asn1crypto` (каноническая форма и RSA над `SignedInfo`; `platform-interop.md`, таблица оракулов); готовой команды для одного вашего файла в репозитории нет **[не проверено: команда зависит от установленного инструмента]**.
4. Сверить: SHA-256 из страницы подтверждения равен хешу файла, подписанный сертификат — ваш (отпечаток SHA-256), подписанный текст байт в байт ваш.
5. Дополнительно (не независимо): `oncl verify <файл>` — собственная проверка проекта, результат прилагать как вторичный.

### 1.6 Что записать

Версия и SHA-256 сборки; версия ОС; тип ключа (RSA/ГОСТ, без серийного номера в публичной записи); операция; хеши файла и сертификата со страницы; что показала страница результата; независимый проверяющий и его вывод; время ответа; найденные дефекты. Скриншоты — без путей, имён пользователей и серийных номеров. Шаблон — раздел 4.

### 2.2 Проверка фокуса при 200 % со скриптом UIA

Скрипт `scripts/uia-secret-probe.ps1` — читает поля секретов через UI Automation и MSAA и падает, если введённый секрет виден в любом свойстве при маскировании. Параметры: обязательный `-Exe <путь к uia_secret_probe.exe>`, необязательный `-Secret` (по умолчанию `UIA-probe-secret-4417`). Код выхода 0 — секрет не раскрыт, 1 — раскрыт. Собрать исполняемый файл (из заголовка скрипта):

```sh
cargo build -p oncl-ui --example uia_secret_probe
```

Результат — `target/debug/examples/uia_secret_probe.exe` (путь для `--example` в Cargo; **[не проверено]** на этом дереве). Запуск в **активном интерактивном сеансе** (UIA не видит отключённый сеанс):

```powershell
pwsh scripts/uia-secret-probe.ps1 -Exe .\target\debug\examples\uia_secret_probe.exe
```

Скрипт сам переключает флажки «Показать пароль»: секрет виден, пока флажок включён (выбор пользователя), и не виден после выключения.

Сам «фокус при 200 %» — отдельная ручная проверка (в ledger — «200 % focus», открыто): тексты ru, en, kk на странице подтверждения после перестановки страницы **не** перепрогонялись.

1. Масштаб приложения 200 %: в `settings.json` (в одноразовом каталоге данных) `{"ui": {"scale": 200}}` — процент от масштаба системы: 100, 125, 150, 175 или 200 (`README.md`, раздел про `ui`); либо «Настройки…» → «Размер окон и текста».
2. Для каждой локали (`"locale"` в `settings.json`: `ru`, `kk`, `en`) пройти «Плагины» до страницы подтверждения (п. 1.4, шаги 4–6), **не нажимая** «Подписать».
3. Проверить: фокус при открытии — на «Отмена»; Enter не подтверждает; Escape отменяет; Tab обходит кнопки, на каждой остановке виден фокус; окно целиком в рабочей области; тело страницы прокручивается клавиатурой (Tab на полосу, PageDown/End/Home).
4. Запустить `uia-secret-probe.ps1` (выше).
5. Экранный диктор: **ни разу не проверялся** (проверялись только имена и прямоугольники UIA). Включить Narrator (Win+Ctrl+Enter), пройти страницу, записать, что он озвучил; отметить, что безымянная область прокрутки (F2: UIA видит безымянный `Window` как остановку Tab) озвучивается без названия.

Что пойдёт в таблицу: локаль, масштаб приложения, масштаб ОС, `focused`/передний план, окно в рабочей области (да/нет, размеры), результат скрипта (0/1).

### 2.3 Перепроверка F1 после исправления

1. Одноразовый `ONCL_DATA_DIR`; для каждого шага 100, 125, 150, 175, 200 прописать `ui.scale` и открыть `openncalayer tools`.
2. Для каждого шага записать прямоугольник окна и рабочую область. Ожидание: окно целиком внутри рабочей области (в смоке 100–150 % были 900×580, 1125×750, 1620×1080).
3. Повторить при ОС-масштабе 125 % и 200 % (параметры экрана Windows; **менять только на ВМ или тестовой машине**, не на рабочей), и при 1366×768 (разрешение экрана ВМ).
