# Runbook матрицы ВМ: WinGet (8 ячеек) и Win7 smoke

Для владельца проекта и, при выданном доступе, для ассистента. Опирается на [`winget.md`](winget.md) (раздел «Проверка установки»), [`winget-installer.md`](winget-installer.md), `scripts/winget/*.ps1` и `xtask/src/winget/cli.rs`; параметры ниже сверены с этими файлами. Пометка **[не проверено]** — команда не исполнялась на ВМ (ВМ, пригодных для этого, на хосте разработки нет), причина указана.

## 0. Главное: что можно и нельзя для alpha.7

Это расхождение надо было решить владельцу до начала матрицы; итог — в [`release-alpha7-status.md`](release-alpha7-status.md).

| Факт | Источник |
|---|---|
| `Invoke-WingetProbe.ps1` и `Invoke-WingetFinalProbe.ps1` принимают только stable-тег `^v\d+\.\d+\.\d+$` и падают на `v0.1.0-alpha.7` | `Invoke-WingetProbe.ps1:62`, `Invoke-WingetFinalProbe.ps1:26` |
| `cargo xtask winget candidate|generate` отвергают черновик, pre-release и тег не вида `v<major>.<minor>.<patch>` | `winget.md`, таблица «Что отвергается» |
| `winget.yml` пропускает не-stable теги | `winget.md` |
| Матрица по `winget.md` выполняется на **опубликованных** байтах stable-релиза; у черновика ассеты не скачать без авторизации | `winget.md`, «Проверка установки» |
| В alpha.7 тем не менее публикуются `openncalayer-0.1.0-alpha.7-win-x64-winget-setup.exe` и `…-win-x86-winget-setup.exe` | `release.md`, §3 шаг 3 |

Следствие: **скриптовую матрицу из 8 ячеек (`Invoke-WingetProbe.ps1` + `Merge-ProbeCells.ps1` + `xtask winget generate`) на alpha.7 запустить нельзя**: она предназначена для первого stable-релиза. Для alpha.7 в этом документе два режима:

- **Режим A (alpha.7, гейт `vm-smoke`).** Те же восемь ячеек и Win7, но без скриптов-проб: ручной список из `winget-installer.md` (пункты 1–6) и дымовой прогон обычных установщиков. Результат — таблица раздела 8, на её основании вы ставите `vm-smoke`.
- **Режим B (первый stable).** Полная скриптовая матрица, раздел 6. Для alpha.7 не выполняется; описана, чтобы её не пришлось переписывать, и потому что вы просили её описать.

Решение о том, что считается «матрицей ВМ» для разблокировки alpha.7 (режим A или изменение скриптов, чтобы они принимали pre-release), принимает владелец. Менять скрипты в рамках этого документа нельзя (они — код выпуска).

## 2. Подготовка каждой ВМ

Для каждой ВМ из 1.1 и 1.2 (`winget.md`, «Проверка установки»):

1. **Чистый снимок**: до всяких установок, **без** Visual C++ Redistributable и **без** OpenNCALayer. Скрипт проверяет это и падает, если программа уже стоит (`Invoke-WingetProbe.ps1`: «OpenNCALayer is already installed on this image: revert to a clean snapshot»); отсутствие Redistributable проверяется по записям в `Uninstall`, но само «чистый образ» подтверждаете вы флагом `-CleanImageAttested`.
2. **`winget` с локальными манифестами** (Win10/11): `winget settings --enable LocalManifestFiles` — один раз при подготовке снимка, только внутри ВМ; настройки хоста не менять. Нужна административная оболочка **[не проверено: поведение на конкретном образе]**. Наличие `winget` на образе Windows 10 x86 **[не проверено]**.
3. **Сеть** до `github.com` (скачивание релиза). Ресурсы `*.githubusercontent.com` тоже должны быть доступны: `winget.md`.
4. **Старый установщик** для проверки upgrade: `openncalayer-<старая>-win-<арх>-setup.exe`. Для alpha.7 «старая» — `0.1.0-alpha.6` (последний тег). Установщики alpha.6 скачиваются из опубликованного релиза. Обратите внимание: alpha.6 собрана без ключа обновлений и без endpoint обслуживания; upgrade «поверх запущенной alpha.6» ожидает код 5 (`winget-installer.md`, «Дополнения к списку ВМ»).
5. **Кандидатный манифест** из `target/winget-candidate` (режим B). В режиме A манифеста нет.
6. **Аккаунты**: стандартный пользователь, и (отдельно) администратор, под которым вы работаете без повышения. Для стандартной учётной записи нужен профиль администратора (`-OtherAdminProfile`): в него UAC-запрос «других учётных данных» не должен ничего записать.
7. **Win7**: чистый снимок Windows 7 SP1 нужной разрядности, без Visual C++ Redistributable (сборки статические, [`install.md`](../user/install.md), «Windows 7»), браузеры Chrome 109 и Firefox ESR 115 для проверки расширения.

Тип ВМ: скрипты распознают ВМ по модели/производителю (`Virtual|VMware|KVM|QEMU|Hyper-V|Xen|Parallels`) или по учётной записи Windows Sandbox; в VirtualBox это пройдёт, если модель содержит `Virtual` **[не проверено на образах VirtualBox]**; в противном случае скрипт откажется работать.

## 3. Что взять из релиза

Из черновика/релиза (`gh release download v<версия> -p '<маска>' -D <каталог>`; флаги `-p`, `-D` — стандартные для `gh release download`, не проверены на этом репозитории):

- `openncalayer-<версия>-win-x64-winget-setup.exe`, `openncalayer-<версия>-win-x86-winget-setup.exe` (WinGet-вход);
- `openncalayer-<версия>-win-x64-setup.exe`, `…-win-x86-setup.exe` (обычные установщики Windows 10/11);
- `openncalayer-<версия>-win7-x64-setup.exe`, `…-win7-x86-setup.exe` (Win7);
- `SHA256SUMS`: проверять размер и хеш каждого файла до запуска: `sha256sum -c` в Git Bash или `Get-FileHash -Algorithm SHA256` в PowerShell.

Для черновика `gh` должен быть авторизован вами: ассистент свою учётную запись для этого не использует.

## 4. Режим A: alpha.7, ручной список по ячейкам

Каждая ячейка 1–8 — один проход под своей учётной записью на ВМ из чистого снимка, **без повышения** (кроме пункта 5). Все команды PowerShell (в ВМ).

Подготовка: `$v = '0.1.0-alpha.7'; $arch = 'x64'` (или `x86`); пути — ваши.

1. **Чистая установка WinGet-входом** — окон нет:

   ```powershell
   $arp = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\OpenNCALayer'
   .\openncalayer-$v-win-$arch-winget-setup.exe --silent --wait 30; "exit=$LASTEXITCODE"
   (Get-ItemProperty $arp).DisplayVersion
   ```

   Ожидается `exit=0`, `DisplayVersion` = `0.1.0-alpha.7`, программа запущена не была (при чистой установке окон нет). Команды `--silent --wait` и ключ реестра — из `winget-installer.md` (шаг 1 списка); коды выхода: 0 успех, 1 прочий сбой, 2 аргументы, 3 payload повреждён, **4 занято**, 5 программу нельзя спросить, 6 Setup ошибка, 7 версия не установилась, 8 повышенный токен, 9 не Windows. Успех — только 0.
2. **Удаление и переустановка**: `winget uninstall` недоступен без манифеста; удаление — штатным деинсталлятором записи Apps & Features (`Update.exe`) или параметром записи реестра `UninstallString` (значение прочитать, не угадывать); затем повторить п. 1. Что запись и каталог `%LOCALAPPDATA%\OpenNCALayer` исчезли — наблюдение; каталог `%APPDATA%\OpenNCALayer` (данные пользователя) удалённым быть не должен **[ожидание по `winget.md`, шаг 6: данные переживают upgrade; поведение удаления в этом поле не проверено]**.
3. **Upgrade поверх старой версии**: установить alpha.6 обычным установщиком (`openncalayer-0.1.0-alpha.6-win-$arch-setup.exe --silent`, ключ `--silent` как в `Invoke-WingetProbe.ps1`), создать контрольный файл `$env:APPDATA\OpenNCALayer\probe-sentinel.txt`, затем запустить WinGet-вход alpha.7:

   - программа alpha.6 **не запущена**: ожидается `exit=0`, `DisplayVersion` = `0.1.0-alpha.7`, контрольный файл цел;
   - программа alpha.6 **запущена** (`openncalayer run`): ожидается `exit=5` (программу нельзя спросить, у alpha.6 нет endpoint), ничего не завершается принудительно, установка не изменена.
4. **Удержание подписи** (ключевая проверка безопасности). Нужна запущенная программа **с endpoint обслуживания**: у alpha.6 его нет (будет код 5, п. 3), у alpha.7 есть. Поэтому: установить alpha.7 (п. 1 или обычным установщиком), запустить `openncalayer run`, начать долгую подпись (большой файл в окне «Инструменты…» или пакет) и запустить WinGet-вход **той же версии** alpha.7 с `--wait 30` (повторная установка, `reinstall`: скрипт `Invoke-WingetProbe.ps1`, шаг 5, делает её же, а `winget-installer.md` отмечает, что entry не отклоняет и понижение версии; поведение именно с запущенной сборкой на ВМ **[не проверено]**). Ожидается `exit=4`, подпись завершается корректно, `DisplayVersion` прежняя. Автоматически это покрывают три теста с настоящим демоном (`crates/openncalayer/tests/maintenance_e2e.rs`: `real_idle_daemon_is_held_for_setup_and_released`, `real_signing_in_flight_gets_busy_and_completes_correctly`, `a_killed_installer_releases_the_real_daemon`; сборка harness `cargo build -p oncl-winget-setup --bin oncl-winget-harness`, запуск `cargo test -p openncalayer --features e2e-prompter --test maintenance_e2e -- --ignored`; команды из `winget-installer.md`), но на настоящих ВМ и настоящем Setup проверка не выполнялась.
   **Без оператора:** `scripts/winget/Invoke-WingetHold.ps1` (PowerShell 5.1, в ВМ, токен без повышения). Окно «Инструменты…» долгую подпись без человека не даёт, поэтому скрипт запускает **тестовую** сборку демона (`cargo build --release -p openncalayer --features e2e-prompter`; на диалоги подписи она отвечает из `steps.json`, окон не открывает; в установку не кладётся и релизным кандидатом не является), шлёт ей подпись так, как это делает relay расширения (канал bridge; ключ `fixtures/synthetic/user-rsa-sign.p12`, корень `root-rsa.cer`), держит подпись не меньше 60 с (шаг `wait_file`) и всё это время запускает **настоящий** WinGet-вход: `exit=4` при `--wait 2` и `--wait 30`; Apps & Features и SHA-256 каждого файла установки не меняются; затем подпись завершается, Windows (`SignedCms`, не код проекта) проверяет её на синтетическом корне, подделанные данные отвергаются; потом окно QUIET (30 с: вход с `--wait 3` даёт `exit=4`) и повторный вход (`exit=0`, версия входа). Результат — `result.json` в стиле ячеек матрицы (шаги, ожидания, вердикт `PASS`/`FAIL`). Ключ `-SafeDryRun` — для машины разработчика: ничего не ставит, не трогает каталог данных по умолчанию и не даёт входу установить (временный каталог входа нарочно непригоден: вход, которому hold выдан, завершается кодом 1 «cannot prepare Setup»); вердикт такого прогона не выше `PASS-DRY-RUN`. Вход и демон должны смотреть в один каталог данных: в ВМ оба берут каталог по умолчанию, в сухом прогоне скрипт передаёт обоим `-DataDir` (иначе вход не находит демона, считает, что программы нет, и идёт дальше к установке). Чего скрипт не доказывает: поведения самого релизного демона alpha.7 (без окон его не подписать) и запуска через `winget upgrade --manifest` (манифеста для alpha.7 нет, раздел 0).
   Состояние: на ВМ скрипт **[не проверено]**. На машине разработчика прогнан только `-SafeDryRun` с настоящими входами alpha.7 (x64, и x86 под WOW64): `exit=4` и при `--wait 2`, и при `--wait 30` (подпись держалась 75 с), подпись цела (Windows и OpenSSL), в окне QUIET снова `exit=4`, после него hold выдан и снят вместе со входом; установка, чей состав скрипт сверяет, на той машине отсутствует, так что «установка не изменена» там не проверка. Установка базовой версии, настоящий последний upgrade и `-UninstallAtEnd` на ВМ ещё не исполнялись.
   **Два клиента endpoint обслуживания одновременно (п. 8, «одновременный штатный updater»):** `scripts/winget/Invoke-WingetTwoClients.ps1` (PowerShell 5.1, в ВМ, чистый образ, токен без повышения; тестовая сборка демона без шагов, тот же пользователь и сеанс, что у входа). Второй обслуживающий клиент по протоколу endpoint — то же самое, что собственный updater программы: оба берут единственный `ActivityGate` процесса (`session.rs::hold_requests_unless`). Случаи: A — два сырых клиента (первый получает hold, второй `busy`, повторно `busy`, `release` без своего hold безвреден, hold первого цел); B — вход при чужом hold даёт `exit=4`, ничего не установлено, hold сырого клиента цел; C — вход ставит программу, пока второй клиент опрашивает каждые 100 мс: `busy` видно, вход `exit=0`. Первая попытка 2026-11-11 провалилась из-за пробы, а не продукта (`$Stream` был `$null`: проба писала в канал, который не открылся); на Windows 11 x64 (токен Medium, 2026-11-11) сценарий прошёл, 15 ожиданий из 15.
5. **Повышенный запуск**: из консоли «Запуск от имени администратора» запустить WinGet-вход: ожидается `exit=8` **до любой записи** (проверить, что `%LOCALAPPDATA%\OpenNCALayer`, профиль другого администратора и `HKLM` не изменились). UAC-подтверждение делаете вы.
6. **Корни доверия и порты**: после установки `certutil -user -store Root` и `certutil -store Root` не должны получить новых записей; `Get-NetTCPConnection -State Listen | Where-Object OwningProcess -in (Get-Process openncalayer).Id` — слушателей вне loopback быть не должно, `oncl-server.exe` в каталоге установки нет (проверки из `Invoke-WingetProbe.ps1`, шаг 8: `no_ca_trust_added`, `http_api_stayed_disabled`). Команды `certutil`/`Get-NetTCPConnection` — стандартные, на образах не прогонялись.
7. **Самообновление**: пока нет более нового релиза, выполнить «Проверить обновления» из меню значка и убедиться, что версия не уходит назад. Для alpha.7 полная проверка невозможна: индекс ещё не публиковался и alpha.6 без ключа (`release.md`, §1). Эту проверку принято считать **невыполненной** (отступление по самообновлению первого выпуска WinGet принято владельцем 2026-11-09, `manual-plugins-status.md`, §6: это отступление, а не пройденная проверка).
8. **Дополнения, наблюдаемые руками** (`winget.md`: «Список из `winget-installer.md`… остаётся чеклистом»): перезапуск ВМ после upgrade, одновременный штатный updater, открытое окно подтверждения, окно «Инструменты», вызов плагина во время установки, установка поверх alpha.6 без endpoint (код 5).

## 5. Win7 smoke (ручной эквивалент прогона лаборатории)

На каждой ВМ W1/W2 (Windows 7 SP1, чистый снимок):

1. Скопировать `openncalayer-<версия>-win7-<арх>-setup.exe` и проверить SHA-256 по `SHA256SUMS`.
2. Запустить установщик (обычный, без администратора: установка идёт в профиль пользователя). Ожидается установка без Visual C++ Redistributable; `win-*` установщики на Win7 отказываются ставиться — это тоже ожидаемо ([`install.md`](../user/install.md), «Установка»).
3. Запустить `openncalayer` (меню «Пуск» или `%LOCALAPPDATA%\OpenNCALayer\current\openncalayer.exe`; точный путь запуска **[не проверено на Win7]**): значок в трее, `openncalayer tools` открывает окно «Инструменты». Окно должно отображаться (шрифты по системным метрикам, DPI; [`install.md`](../user/install.md), «Windows 7»), список подписи, форма доступны.
4. Перезагрузка ВМ после установки; программа стартует автоматически (автозапуск `HKCU\…\Run` включён установщиком); relay `nmhost.exe` зарегистрирован.
5. Расширение: Chrome 109 и Firefox ESR 115: установить расширение, проверить, что страница видит NCALayer через расширение (проверка ручная, шаги — [`browser-extension.md`](../user/browser-extension.md)).
6. Деинсталляция через «Программы и компоненты» или `Update.exe`; перезагрузка; в каталоге пользователя не остаётся автозапуска, relay-манифестов.
7. Фиксировать: версия ОС (`ver`), разрядность, SHA-256 установщика, результат каждого пункта, скриншоты **без** имён пользователей и путей (правило `cargo xtask privacy` запрещает пути с буквой диска и имена машин в публичных файлах).

Окно «Плагины» на Win7 и DPI-проверки — в [`manual-checks-runbook.md`](manual-checks-runbook.md), раздел (c).

Статус: на сборке alpha.7 установщики `win7-x64` и `win7-x86` из черновика релиза были прогнаны на Win7 SP1 (установка, запуск, перезагрузка с автозапуском, удаление, окно «Инструменты»); итог — [`release-alpha7-status.md`](release-alpha7-status.md). Расширения на Win7 не проверялись. На alpha.3 прогон лаборатории был ([`install.md`](../user/install.md), «Windows 7»).

## 6. Режим B: скриптовая матрица для первого stable-релиза

Только когда есть **опубликованный stable-релиз** `v<major>.<minor>.<patch>` с подписанными (SignPath) `…-winget-setup.exe` для x64 и x86.

### 6.1 Кандидат (на вашей машине, Git Bash)

```sh
gh api repos/<репозиторий>/releases/tags/v<версия> > release.json
cargo xtask winget candidate --release-json release.json --out target/winget-candidate
```

(команда из `winget.md`, §1; параметры `--release-json`, `--out` (по умолчанию `target/winget-candidate`), необязательные `--ledger`, `--evidence` — из `xtask/src/winget/cli.rs`). Выдаёт каталог из трёх файлов `arynyklas.OpenNCALayer*.yaml` и `target/winget-candidate.evidence.json`; кандидат не подаётся.

### 6.2 Ячейка (в ВМ, PowerShell, без повышения)

Реальные параметры `scripts/winget/Invoke-WingetProbe.ps1` (из блока `param`): обязательные `-ManifestDir`, `-InstallerArch` (`x64`|`x86`), `-Tag`, `-OldSetup`, `-OldVersion`, `-Account` (`standard`|`admin_non_elevated`), `-OutFile`; необязательные `-Repository` (по умолчанию `arynyklas/OpenNCALayer`), `-OtherAdminProfile`, `-SelfUpdateTargetVersion`, `-SelfUpdateWaitMinutes` (15), переключатель `-CleanImageAttested`.

```powershell
.\Invoke-WingetProbe.ps1 -ManifestDir .\candidate -InstallerArch x64 -Tag v<версия> `
    -OldSetup .\old\openncalayer-<старая>-win-x64-setup.exe -OldVersion <старая> `
    -Account standard -OtherAdminProfile (Join-Path $env:SystemDrive 'Users\<админ>') `
    -CleanImageAttested -OutFile .\cell-x64-w10-std.json
```

Для ячейки администратора: `-Account admin_non_elevated` (`-OtherAdminProfile` не нужен). Скрипт откажется работать: не в ВМ или Sandbox, с повышенным токеном, при несовпадении `-Account` с типом пользователя, на образе, где программа уже стоит.

Что он делает по шагам (по тексту скрипта): среда; скачивание опубликованного установщика и сверка SHA-256 с кандидатом, `Get-AuthenticodeSignature`; повышенный запуск (код 8); `winget install --manifest … --architecture <арх> --silent` с наблюдением за командной строкой дочернего процесса; тот же без режима (`SilentWithProgress`); upgrade со старой версии с контрольным файлом; удержание подписи; self-update; безопасность (корни, слушатели); удаление. Запись JSON отчёта пишется в `-OutFile`. Запросы оператора в самом скрипте: **Read-Host** на удержании подписи («start a LONG signature… then press Enter»), ответ `y/n` «Did the signature finish correctly?», подтверждение «no signature or window active», подтверждение UAC-запроса при повышенном запуске, и вызов «Проверить обновления» в меню значка при `-SelfUpdateTargetVersion`.

Пока более нового релиза нет, `-SelfUpdateTargetVersion` не задаётся, самообновление не проверяется, и вердикт максимум `submittable-with-waiver` (отказ записывает **владелец**; `winget.md`).

### 6.3 Итоговая ячейка (минимум по одной на архитектуру)

Параметры `Invoke-WingetFinalProbe.ps1`: `-ManifestDir`, `-InstallerArch`, `-Tag`, `-OldSetup`, `-OldVersion`, `-OutFile`. Каталог для неё делается заранее: `cargo xtask winget generate --release-json release.json --probe <probe.json> --out target/winget --final-proof-pending` (флаг `--final-proof-pending`: вывод помечен NOT READY, подавать нельзя). Затем в ВМ:

```powershell
.\Invoke-WingetFinalProbe.ps1 -ManifestDir .\final -InstallerArch x64 -Tag v<версия> `
    -OldSetup .\old\openncalayer-<старая>-win-x64-setup.exe -OldVersion <старая> -OutFile .\final-x64.json
```

### 6.4 Слияние и итоговый манифест (ваша машина)

```powershell
pwsh scripts/winget/Merge-ProbeCells.ps1 -Cells ./cells/*.json -FinalCells ./final/*.json `
    -AttestedBy <имя> -RunId <идентификатор> -OutFile winget/probes/<версия>.json
```

`-PendingFinal` (набор без итоговых ячеек) — только для `generate --final-proof-pending`. Дальше:

```sh
cargo xtask winget generate --release-json release.json --probe winget/probes/<версия>.json --out target/winget
cargo xtask winget check target/winget
winget validate target/winget
cargo xtask winget check --for-submission target/winget --release-json release.json --probe winget/probes/<версия>.json
```

`generate` заново скачивает установщики и принимает отчёт, только если каждое утверждение верно для этих байт; `check --for-submission` пересчитывает вердикт из входов. Подача в `microsoft/winget-pkgs` — только по вашей отдельной команде (`winget.md`, раздел «Подача»); скрипты, workflow и ассистент этого не делают.

Для первого запуска скриптов важно: `winget.md` («Что не доказано») прямо говорит, что `Invoke-WingetProbe.ps1` **внутри ВМ ни разу не запускался**: первая настоящая матрица может найти ошибки скрипта, которые надо исправить до записи отчёта.

## 7. Как результаты становятся статусом `vm-smoke`

- `vm-smoke` — статус коммита тега ядра: контекст `vm-smoke`, состояние `success` (`xtask/src/index.rs`, константа `VM_SMOKE`; `index check` читает его через `GET /repos/<репозиторий>/commits/<тег>/status`).
- Ставите его вы, когда **вся** таблица раздела 8 (режим A) закрыта PASS: восемь ячеек WinGet и обе Win7. Команда — в [`release-runbook-alpha7.md`](release-runbook-alpha7.md), раздел 6.4. Красный итог: `failure`, черновик не публикуется.
- Отчёты режима B (JSON проб) в статус `vm-smoke` напрямую не превращаются: они — свидетельство для генератора манифеста WinGet; `vm-smoke` ставится по общему итогу лаборатории.
- JSON-отчёты коммитятся в `winget/probes/<версия>.json`; перед коммитом `cargo xtask privacy` (отчёты хранят версии, хеши, коды и признаки, не пути и имена пользователей).

## 9. Что автоматизирует ассистент, если дан доступ к ВМ

Автоматизация **ещё не написана**; ниже — что она потребует и как делать безопасно. Всё — **[не проверено]**: ВМ, доступ к которым есть у ассистента, на хосте разработки не предоставлены.

### 9.1 Что нужно от вас (одно из)

| Способ | Что требуется | Замечания |
|---|---|---|
| Hyper-V на хосте | Роль Hyper-V включена (по файлам: компонент установлен), но права управления ВМ у учётной записи ассистента **не подтверждены** (`winget-installer.md`: «список ВМ недоступен без прав»). Нужна членство в группе «Администраторы Hyper-V» или явно выданные права; для заходов в гостя — PowerShell Direct (хост Windows 10+/Server 2016+, гость Windows 10+; **не работает с Win7**) | Контрольные точки: `Checkpoint-VM`, `Restore-VMCheckpoint`, `Get-VM` — стандартные командлеты, на хосте не запускались |
| WinRM в госте | В госте `Enable-PSRemoting`, доступный порт, учётная запись; лучше HTTPS-слушатель; на хосте — разрешение подключения к этому гостю | Для Win7 WinRM из составного PowerShell 2.0/WMF; **не проверено**; обычная учётная запись должна быть залогинена для UAC-проверок (см. 9.3) |
| SSH в госте | OpenSSH Server в госте (Windows 10/11); для Win7 — стороннее решение | Хост-ключ сверить заранее |
| RDP | Интерактивный сеанс для проверок с окнами | Нужен для шагов, которым нужен передний план (раздел 9.3) |

VirtualBox на рабочей станции установлен (по файлам), там есть ВМ, назначение которых не проверялось (по названиям — для оригинального NCALayer): **не использовать их как «чистые»**: на них стоит оригинал и нет чистого снимка. Если VirtualBox выберете вы, ассистенту нужны имена ВМ и снимков и подтверждение, что управление идёт через `VBoxManage` (на хосте не запускался).

### 9.2 Безопасная процедура на каждую ячейку

1. Откатить ВМ к **чистому** снимку (контрольная точка / снимок) и включить сеть, достаточную для `github.com`.
2. Скопировать в ВМ только: установщик(и), старый установщик, скрипты (`scripts/winget/*.ps1`), `SHA256SUMS`, кандидатный манифест. **Не копировать** токены GitHub, ключи подписи индексов, пароли ключевых хранилищ, SignPath-токены.
3. Проверить SHA-256 скриптов и установщиков (скрипт сам пишет в отчёт `script_sha256`).
4. Запустить пробу/дымовой список под нужной учётной записью; собрать `cell-*.json`/логи.
5. Скопировать результаты **с ВМ на хост** (не наоборот), затем откатить ВМ к чистому снимку. Рабочие каталоги ВМ не оставлять.
6. Прогнать `cargo xtask privacy` над собранным (отчёты не должны содержать путей машин, имён пользователей, имён хостов).

### 9.3 Что ассистент автоматизирует и что остаётся вам

| Шаг | Автоматизируется | Остаётся вам |
|---|---|---|
| Откат ВМ, копирование, запуск, сбор JSON | да, при доступе (9.1) | — |
| Чистая установка, upgrade, uninstall, коды выхода, ARP, `--version`, корни, слушатели | да (то, что делают `Invoke-WingetProbe.ps1`/ручной список) | — |
| Скачивание и сверка хешей, `Get-AuthenticodeSignature` | да | — |
| Запрос UAC при повышенном запуске | **нет** (нужен интерактивный рабочий стол; тип «другие учётные данные» требует пароль администратора) | вы нажимаете «Да»/вводите учётные данные в сеансе RDP |
| Долгая подпись в запущенной программе во время запуска WinGet-входа (hold, код 4) | **да**, без окон: `scripts/winget/Invoke-WingetHold.ps1` с тестовой сборкой демона (`e2e-prompter`) и синтетическим ключом, см. раздел 4, п. 4 (на ВМ скрипт **[не проверено]**: на машине разработчика прогнан только его `-SafeDryRun`); не покрыто: настоящая подпись через окно «Инструменты…» (нужен интерактивный рабочий стол; в автоматике — три теста `maintenance_e2e`) | вы только запускаете скрипт и читаете `result.json` |
| «Проверить обновления» из меню значка | нет (меню значка не доступно программно; smoke 2026-11-07: контекстное меню не открылось синтетическим кликом) | вы |
| Win7: установка, перезагрузка, окно, расширения | нет сценария в репозитории; написать можно только после доступа к ВМ | вы, до этого |
| Решение PASS/FAIL, статус `vm-smoke` | нет | вы |

Секреты не попадают в журналы: ни ассистент, ни скрипты не получают ключ подписи индексов, токены, пароли хранилищ; журналы команд ассистента не содержат аргументов с секретами (передавать пути, не пароли; пароль ключевого хранилища вводится вами).

## 10. Что проверено и что нет

- Проверено чтением: параметры, регулярные выражения тега, шаги и запросы оператора в скриптах; подкоманды и флаги `cargo xtask winget candidate|generate|check`; восемь ячеек и их охват; коды выхода установщика; контекст статуса `vm-smoke`.
- Не проверено: ни одна команда на настоящей ВМ; наличие `winget` на образах; распознавание VirtualBox как ВМ скриптом; поведение `winget`-входа alpha.7 в Windows 10 x86.
