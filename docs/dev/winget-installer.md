# Установщик для WinGet (`oncl-winget-setup`)

WinGet запускает установщик и верит его коду возврата. Закреплённый Velopack `Setup.exe` при переустановке принудительно завершает установленную программу (в том числе посреди подписи), а при невыполненных prerequisites выходит с кодом 0, ничего не поставив. Поэтому в WinGet-ассет кладётся не он, а маленькая программа `oncl-winget-setup`, которая несёт **неизменённый** `Setup.exe` и сама решает, можно ли его запускать. Артефакт: `openncalayer-<версия>-win-<x64|x86>-winget-setup.exe` (только Windows 10 1809+; Win7-флейворы WinGet-установщика не имеют и сохраняют обычные установщики).

## Что делает

1. Отказывается работать с повышенным токеном (установка идёт в профиль пользователя, до любых записей).
2. Читает payload из собственного образа и проверяет SHA-256, версию и архитектуру (`payload.rs`: payload лежит сразу после последней секции PE, перед сертификатной таблицей Authenticode; после таблицы данных быть не может).
3. Если программа установки запущена, просит её через **отдельный** per-user endpoint управления (`oncl_ipc::maintenance`, не WSS и не native messaging) «замереть»: тем же решением, что у штатного updater (`Host::hold`): сначала новые запросы удерживаются, потом проверяются активные операции, QUIET и открытые окна. Hold живёт, пока жива IPC-связь: убитый установщик не оставляет программу занятой навсегда (плюс предел `MAX_LEASE`). Занято дольше `--wait` (по умолчанию 180 с) — код 4, установка нетронута. Запущенная программа без endpoint (старая версия) — код 5; ничего не завершается принудительно.
4. Распаковывает payload в приватный каталог и запускает `Setup.exe --silent` (без других ключей).
5. Код возврата Setup ничего не доказывает: проверяются манифест по локатору Velopack, установленная программа (`--version`) и запись HKCU Apps & Features (версия, расположение, деинсталлятор).
6. После доказанной установки запускает снова программу, которая работала до неё; при чистой установке окон не открывает.

Коды: 0 успех; 1 прочий сбой; 2 аргументы; 3 payload повреждён/отсутствует; **4 занято**; 5 программу нельзя спросить; 6 Setup завершился ошибкой; 7 Setup вышел, но нужная версия не установлена; 8 повышенный токен; 9 не Windows. Успех — только 0 (WinGet: `InstallerSuccessCodes` не расширять).

## Порядок выпуска (release.yml)

Сборка entry (`--no-default-features`, без тестового harness) → `vpk pack` → Authenticode `Setup.exe` (если SignPath настроен) → `cargo xtask package winget-setup` вкладывает **итоговый** `Setup.exe` в entry → Authenticode самого entry (отдельный запрос SignPath, артефакт `signpath-unsigned-winget-setup-<флейвор>`; в конфигурации артефакта SignPath должен быть разрешён `*-winget-setup.exe`) → публикуются именно эти байты → один раз скачать, сверить SHA-256 → манифест WinGet (Task 38). Без SignPath entry публикуется неподписанным, в журнале notice; подпись не выдумывается.

## Что проверено на этом хосте и что нет

Проверено реальными процессами и реальным per-user IPC (`cargo test -p oncl-winget-setup --test maintenance`): активная операция не прерывается и Setup не стартует; новые операции блокируются на время lease; убитый установщик освобождает программу; открытое окно и незавершённый QUIET дают «занято»; Setup с кодом 0 без установки и неверная версия (манифест, ARP, программа, расположение, архитектура) — отказ. Вместо Velopack Setup используется **harness** (`oncl-winget-harness`: поддельный рабочий стол за настоящим `ActivityGate` и поддельный Setup, пишущий в одноразовый каталог и одноразовый ключ HKCU `OpenNCALayer-test-*`); реальный Setup пишет настоящий ARP и на одноразовый корень не перенаправляется.

**Не выполнено (предусловие выпуска, VM отсутствует: Hyper-V включён, но без прав список ВМ недоступен, Windows Sandbox не установлен; WinGet на хосте не запускался):** на чистых Windows 10/11 x64 и x86 ВМ (обычный пользователь и администратор с неповышенным токеном):

1. Старая версия установлена обычным установщиком; в программе запущена долгая подпись (или пакет). `winget upgrade --manifest <каталог> --silent` → код 4, подпись завершается корректно, установка не изменена (`Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\OpenNCALayer` — прежняя `DisplayVersion`).
2. То же с открытым окном подтверждения, ручными инструментами и вызовом плагина.
3. Простой upgrade: код 0, новая `DisplayVersion`, программа запущена снова; параллельно штатный updater (hold exclusive: один из них получает «занято»); перезапуск ВМ; сохранность `%APPDATA%\OpenNCALayer`.
4. Чистая установка: окон нет; `winget uninstall`; reinstall.
5. Повышенный запуск → код 8 до записи.
6. ProbeReport (Task 38): на чистой ВМ без VC++ Redistributable установщик запускается и ставит версию.

Минимальный скрипт проверки шага 1 (PowerShell в ВМ, неповышенный):

```powershell
$arp = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\OpenNCALayer'
(Get-ItemProperty $arp).DisplayVersion          # до
.\openncalayer-<версия>-win-x64-winget-setup.exe --silent --wait 30; "exit=$LASTEXITCODE"   # при активной подписи ожидается 4
(Get-ItemProperty $arp).DisplayVersion          # не изменилась
```

## Шаг оператора: конфигурация артефакта SignPath

Репозиторий не меняет ни секреты, ни серверные настройки SignPath; перед первым релизом с WinGet-установщиком мейнтейнер один раз добавляет в **проект SignPath** (не в этот репозиторий) то, что `release.yml` отправляет на подпись отдельным запросом: артефакт `signpath-unsigned-winget-setup-<флейвор>` — это zip с одним `openncalayer-<версия>-win-<x64|x86>-winget-setup.exe`. В конфигурацию артефакта (`artifact-configuration`, ту же, что подписывает `signpath-unsigned-setup-*`, либо отдельную, на которую указывает `SIGNPATH_SIGNING_POLICY_SLUG`) должен входить элемент `<pe-file path="*-winget-setup.exe">` с тем же Authenticode-шагом. Пока этого нет, SignPath отклонит запрос, и job `binaries` упадёт, а не выпустит неподписанный файл; без секретов SignPath шаги пропускаются, и установщик публикуется неподписанным с notice в журнале (подпись не выдумывается).

## Гонка «программа запустилась, пока готовился Setup»

Если при первом взгляде ни программы, ни её процессов нет, установщик готовит приватную копию payload и **ещё раз** (один раз, без повторов) пытается удержать программу прямо перед запуском Setup: программа, успевшая стартовать, получает обычный hold. Остаётся промежуток между этим взглядом и тем, как сам Setup завершает процессы установки; закрыть его можно только изменением Setup (закреплённый Velopack не меняется). Запущенный в этот миг демон только что стартовал и операций не имеет, но формально может быть остановлен.

## Что считается операцией (учёт в одном `ActivityGate`)

| Старт | Как учитывается |
|---|---|
| Запрос модуля страницы по WSS и через bridge (в том числе вызовы плагинов, это те же модули) | `session::dispatch` берёт `ActivityLease` на время обработки |
| Операции окна «Инструменты» (подпись, хеш, сведения) | `Engine::with_activity`: lease привязан к `OperationLease` и живёт, пока последний владелец операции (контекст, нативный worker, ответ) не отпустит её |
| Открытое окно (подтверждение, настройки, мастер TLS, плагины) | `DaemonHost::hold` спрашивает `window_open` уже после hold |
| Штатный updater, второй установщик | тот же `hold` (исключительный) |
