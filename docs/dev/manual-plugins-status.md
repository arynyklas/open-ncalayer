# Плагины в окне ручных инструментов: что НЕ сделано

Состояние на 2026-11-08, tip интеграционной ветки `c5799246`. Источники: ledger `progress.md` плана платформы, файлы ревью стадий MP (`mp*/review*.md`, `rereview*.md`), код этого дерева. Пункт попадает сюда, если он не сделан, не доказан или принят как предел; закрытые пункты не перечислены. Пользовательское описание — [docs/user/manual-plugins.md](../user/manual-plugins.md), устройство — [docs/design/manual-plugins.md](../design/manual-plugins.md) (стадии в §9.3).

**Главное в одной строке:** модель разрешений, раннер, страница и 27 объявленных операций влиты и проверены тестами с настоящими модулями портов и синтетическими ключами RSA; **ни одна подпись не проходила через настоящее окно с настоящим ключом и службами НУЦ, пакеты с операциями не выпущены, а результат окно не отдаёт (только показывает первые 2 000 знаков)**.

## 2. Известные пределы самой модели

Записаны в ledger как честные пределы и остаются верны:

- **`UserConfirmation::after_user_confirmed` — публичный метод.** Гарантия «подтверждение делает только страница» обеспечена кодом: единственное место вызова (`consent::user_confirmed`), значение `PressToken` как условие, запрет остальных вызовов настройкой clippy (`disallowed-methods`) и тест, который сканирует дерево. Ревью MP5a показало, что `PressToken` внутри модуля страницы можно создать из другого места, а не только из обработчика кнопки, и проверки это пропускают; враждебный код внутри самой программы мог бы подделать подтверждение.
- **Целостность файла хранилища ключей** — граница доверия хоста. Ядро сверяет отпечаток сертификата (`certificate-changed`, `certificate-mismatch`), но не защищает хранилище.
- **`plugin_prepare` открывает ключ** до подтверждения: пароль или PIN вводятся до показа страницы подтверждения; хост обязан собрать секрет заранее; причина неудачи открытия не сохраняется (`KeyUnavailable`).
- **Один одобренный вызов на движок** (`busy`): плагин может держать слот до дедлайна вызова; вызов, получивший `busy`, расходует своё одобрение. Срок одобрения (120 с) измеряется монотонными часами (`Instant`), которые могут не идти во сне системы.
- **Подпись в ответе плагина не проверяется**, а ответ — недоверенный текст.
- **Страница подтверждения не перепроверяет реестр в момент подтверждения** (до 5 минут простоя); снятый плагин может выполниться один раз, подмена пакета невозможна (хеш пакета входит в одобрение).
- **Ядро не различает** похожие символы разных алфавитов, неразрывные пробелы и формы нормализации Юникода в тексте; страница обязана показывать текст как есть (с SHA-256), сравнение на глаз ненадёжно.
- **GOST через окно не проверялся**: независимые оракулы (OpenSSL, lxml) проверяют только RSA; метка времени проверена только по наличию токена в CMS.

## 4. Расхождения в документации, найденные при MP12

Исправлено в этом коммите (доказано кодом):

- `docs/user/http-api.md`: «No shipped manifest declares operations yet» устарело (27 операций в 8 манифестах, ни одна не `server = true`); строка `caller-mismatch` (`plugin_grants.rs`: чужой токен даёт `not-granted`, `caller-mismatch` — только не-клиент сервиса); заголовок списка идентификаторов («ids a server answer carries in practice»); правило пропуска гранта для `derived`; границы конфигурации (16 плагинов, 256 грантов, 72 импорта, 8 ключей, 16 адресов по 2048 байт, идентификаторы 64 байта, умолчания 1 МиБ/256 КиБ, `pki_endpoints` у сервера только GET).
- `docs/user/server.md`: единицы пределов (версия — 64 знака, идентификаторы — 64 байта); правило кадров `0x80` (читатель его не реализует: любой неизвестный вид — повреждение); добавлен раздел «Operator guidance for plugin grants» (грант `plugin_bytes`, поля аудита, заметка об откате, ручное окно вне журнала).
- `docs/user/cli.md`: причина `not-granted` (CLI сверяет плагин и операцию, чужой ключ — обычный `PermissionDenied`); предел 80 для `--allow-import`; правило символов для текстового параметра; что поставляемые операции не `server = true`.
- `docs/dev/plugins-manual-tests.md`: «проводка на tip выдаёт только POST» устарело (GET и POST есть, `InstanceLimits::default()` остаётся).
- `docs/design/manual-plugins.md`: §4.1 (CRLF) и §9.3 (статусы стадий).

Не исправлено (вне задания или не доказано): `docs/design/plugins.md:182` (CRLF, п. 7 раздела 1); утверждение ledger «28 операций» (п. 11).

## 5. Как перепроверить

- Манифесты и число операций: `cargo xtask plugin-ops-check` (линтер) и `grep -c '^\[\[operations\]\]' plugins/*/plugin.toml`.
- Порты настоящими модулями: `cargo xtask plugin-ports-manual` ([docs/dev/plugins-manual-tests.md](plugins-manual-tests.md)).
- Таблица подкодов страницы: `crates/oncl-core/src/plugins/refusal.rs` (`PluginRefusalCode::ALL`; тест `PINNED` фиксирует список).
